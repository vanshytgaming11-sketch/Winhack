Module 5.7 — Modern Utilities

This final sub-topic of Module 5 covers four utility types from modern C++ that solve specific, common problems: grouping heterogeneous values (tuple), representing "a value that might not exist" (optional), representing "one of several possible types" (variant), and wrapping any callable thing uniformly (function).

1. std::tuple

Where pair (Module 4.2) holds exactly two values, tuple generalizes this to hold any number of values of potentially different types. 

#include <tuple>
using namespace std;

tuple<int, string, double> t1(22, "Vinit", 8.5);
auto t2 = make_tuple(20, "Aman", 9.1);   // type-deduced construction

cout << get<0>(t1) << " " << get<1>(t1) << " " << get<2>(t1);   // 22 Vinit 8.5
// Access is by COMPILE-TIME INDEX via get<N>() — there's no .first/.second/.third generalization

Structured Bindings with tuple (cleaner than repeated get<N>())

tuple<int, string, double> student(22, "Vinit", 8.5);
auto [age, name, gpa] = student;   // unpacks all three values at once (Module 5.6)
cout << age << " " << name << " " << gpa;

Returning Multiple Values from a Function

tuple<int, int, int> minMaxSum(vector<int> &v) {
    int mn = v[0], mx = v[0], sum = 0;
    for (int x : v) {
        mn = min(mn, x);
        mx = max(mx, x);
        sum += x;
    }
    return {mn, mx, sum};
}

int main() {
    vector<int> v = {5, 2, 9, 1, 7};
    auto [minVal, maxVal, total] = minMaxSum(v);
    cout << minVal << " " << maxVal << " " << total;   // 1 9 24
    return 0;
}

When to use tuple vs a struct: for two or three loosely related, temporary values (especially inside a single function), tuple is quick and convenient. For anything with real semantic meaning that's used across multiple functions, a named struct is almost always clearer — field names like .age communicate intent far better than get<0>().

2. std::optional (C++17+)

Represents a value that may or may not be present — a type-safe alternative to using a sentinel value (like -1 or nullptr) to mean "no result," which can be ambiguous if the sentinel is also a valid actual value. 

#include <optional>
using namespace std;

optional<int> findValue(vector<int> &v, int target) {
    for (int x : v) {
        if (x == target) return x;   // wraps the found value
    }
    return nullopt;   // explicitly represents "no value found" — nullopt is optional's equivalent of nullptr
}

int main() {
    vector<int> v = {10, 20, 30};

    optional<int> result = findValue(v, 20);
    if (result.has_value()) {
        cout << "Found: " << result.value();   // Found: 20
    }

    optional<int> result2 = findValue(v, 99);
    if (!result2) {                                 // optional also supports direct bool-context checking
        cout << "Not found" << endl;                 // this runs
    }

    cout << result2.value_or(-1);                       // -1 — provides a fallback default if empty, safely
    return 0;
}

Why This Is Better Than a Sentinel Value

// The OLD, ambiguous way — using -1 to mean "not found":
int findValueOld(vector<int> &v, int target) {
    for (int x : v) if (x == target) return x;
    return -1;   // AMBIGUOUS: what if -1 is a legitimately valid value that WAS actually in the vector?
}

// optional<int> removes this ambiguity entirely — "no value" and "the value -1" are now
// distinguishable states, both representable and neither confused with the other.

Critical gotcha: calling .value() on an empty optional throws std::bad_optional_access — always check .has_value() (or use .value_or() for a safe default) before accessing.

3. std::variant (C++17+)

A type-safe union — holds a value that could be ONE of several specified types at any given time, and tracks which type is currently active. Unlike a C-style union, variant knows its own active type and prevents reading it as the wrong one. 

#include <variant>
using namespace std;

variant<int, string, double> v;

v = 42;
cout << get<int>(v);         // 42 — access by TYPE

v = "Hello";
cout << get<string>(v);        // Hello — v now holds a string instead

v = 3.14;
cout << get<double>(v);           // 3.14

// Attempting to get<> the WRONG currently-inactive type throws std::bad_variant_access:
v = 42;
// cout << get<string>(v);   // THROWS — v currently holds an int, not a string

cout << v.index();     // 0 — returns the index (0-based, matching declaration order) of the CURRENTLY active type

Safely Checking the Active Type — holds_alternative

variant<int, string> v = "Hello";

if (holds_alternative<string>(v)) {
    cout << "Currently holds a string: " << get<string>(v);
} else if (holds_alternative<int>(v)) {
    cout << "Currently holds an int: " << get<int>(v);
}

Processing a variant Generically with visit

variant<int, string, double> v = 3.14;

visit([](auto &&value) {   // a generic lambda — automatically handles WHICHEVER type is currently active
    cout << "Value: " << value;
}, v);

Common use case: representing a value that could legitimately be one of several distinct types — e.g., a JSON-like value (number, string, boolean), or a parser result that could be either a successfully parsed value or an error description.

4. std::function

A general-purpose, polymorphic wrapper that can store ANY callable entity — a regular function, a function pointer, a lambda (with or without captures), or a functor (an object with operator()) — as long as its call signature matches. 

#include <functional>
using namespace std;

int add(int a, int b) { return a + b; }

function<int(int, int)> f1 = add;                              // wraps a regular function
function<int(int, int)> f2 = [](int a, int b) { return a * b; }; // wraps a lambda

int x = 10;
function<int()> f3 = [x]() { return x * 2; };                   // wraps a lambda that captures state

cout << f1(3, 4) << " " << f2(3, 4) << " " << f3();   // 7 12 20

Why std::function Matters — Storing Heterogeneous Callables

vector<function<int(int)>> operations;

operations.push_back([](int x) { return x + 1; });
operations.push_back([](int x) { return x * 2; });
operations.push_back([](int x) { return x * x; });

for (auto &op : operations) {
    cout << op(5) << " ";   // 6 10 25 — a single container holds THREE DIFFERENT lambda types uniformly
}

This is precisely the limitation function pointers (Module 3.4) couldn't overcome: a raw function pointer variable can only store things matching a plain function signature, and cannot hold a lambda that captures state. std::function erases these differences behind one uniform, storable type — at the cost of a small runtime overhead compared to a raw function pointer or a directly-typed lambda (via auto).

Using std::function as a Class Member (Callback Pattern)

class Button {
    public:
        function<void()> onClick;   // can be assigned ANY callable matching void()

        void click() {
            if (onClick) onClick();   // std::function is bool-convertible — checks if it holds a valid target
        }
};

int main() {
    Button b;
    b.onClick = []() { cout << "Button clicked!" << endl; };
    b.click();   // Button clicked!
    return 0;
}

Conceptual

  1. When would you prefer tuple over a named struct, and vice versa?
  2. Explain the ambiguity problem optional solves compared to using a sentinel value like -1 to represent "no result."
  3. What's the difference between a C-style union and std::variant in terms of type safety?
  4. Why can a raw function pointer not store a lambda that captures surrounding variables, while std::function can?
  5. What happens if you call get<string>(v) on a variant<int,string> that currently holds an int?

  3. Write a program using variant<int, string, bool> to represent a simple configuration value, and use visit with a generic lambda to print each value regardless of its active type.
  4. Write a simple event system class that stores a vector<function<void(string)>> of "listeners," with a method to add a listener and a method to trigger all of them with a given message.
