Module 5.6 — Modern STL Usage

This module covers three syntax-level improvements introduced across C++11–C++17 that make everyday STL usage cleaner and, in one case, meaningfully faster: emplace_back(), range-based for loops (already used informally throughout this course, formalized here), and structured bindings.

1. push_back() vs emplace_back()

Both add an element to the end of a container like vector. The difference: push_back() takes an already-constructed object (and copies or moves it in), while emplace_back() takes the CONSTRUCTOR ARGUMENTS directly and constructs the object in place, inside the container's memory — avoiding an extra temporary object and its associated copy/move entirely. 

class Student {
    public:
        string name;
        int age;
        Student(string n, int a) : name(n), age(a) {
            cout << "Constructed: " << name << endl;
        }
        Student(const Student &other) : name(other.name), age(other.age) {
            cout << "Copied: " << name << endl;
        }
};

int main() {
    vector<Student> students;

    students.push_back(Student("Vinit", 22));
    // Step 1: constructs a TEMPORARY Student("Vinit", 22)   → prints "Constructed: Vinit"
    // Step 2: MOVES (or copies) that temporary into the vector → possibly prints "Copied: Vinit"
    // Two steps total: one construction + one copy/move

    students.emplace_back("Aman", 20);
    // Constructs the Student DIRECTLY inside the vector's memory, using the given arguments
    // Only prints "Constructed: Aman" — NO temporary object, NO copy/move step at all

    return 0;
}

Why This Matters — Performance

For simple types like int, the difference is negligible. But for classes with expensive copy/move operations (large objects, or objects without a cheap move constructor), emplace_back() can meaningfully reduce unnecessary construction/copy overhead, especially inside tight loops adding many elements. 

vector<pair<int,string>> v;

v.push_back(make_pair(1, "a"));   // constructs a pair, then copies/moves it in
v.emplace_back(1, "a");              // constructs the pair DIRECTLY in place — no intermediate temporary

When They Behave Identically

vector<int> v;
v.push_back(5);        // for simple types, both are essentially equivalent — negligible difference
v.emplace_back(5);

Modern best practice: default to emplace_back() for container elements that are class/struct types, since it's never slower and is often faster — but readability is also a valid consideration, since push_back(Student("Vinit", 22)) is arguably more explicit about what's being constructed than emplace_back("Vinit", 22).

2. Range-Based For Loops (Formal Recap)

Already used informally since Module 1.2 — here's the complete, formal picture, including how it interacts with auto and const-correctness (fully covered in Module 5.1).

vector<int> v = {1, 2, 3, 4, 5};

for (int x : v) { /* x is a COPY */ }               // read-only use, but copies each element
for (int &x : v) { x *= 2; }                          // MODIFIES v in place
for (const int &x : v) { cout << x; }                   // read-only, NO copy — best practice for large types
for (auto &x : v) { x *= 2; }                              // same as above, with type deduction

Range-Based For Over a map

map<string, int> ages = {{"Vinit", 22}, {"Aman", 20}};

for (const auto &entry : ages) {         // entry is a const reference to pair<const string, int>
    cout << entry.first << ": " << entry.second << endl;
}

Range-Based For Over a Raw Array

int arr[5] = {10, 20, 30, 40, 50};
for (int x : arr) {   // works on plain arrays too, since the compiler knows the array's size at compile time
    cout << x << " ";
}

3. Structured Bindings (C++17+)

Structured bindings let you unpack a pair, tuple, or struct's members directly into named variables in a single statement, eliminating repetitive .first/.second access. 

pair<int, string> p = {22, "Vinit"};

// Before structured bindings:
int age = p.first;
string name = p.second;

// With structured bindings (C++17+) — much cleaner:
auto [age2, name2] = p;
cout << age2 << " " << name2;   // 22 Vinit

The Killer Use Case — Iterating a map

map<string, int> ages = {{"Vinit", 22}, {"Aman", 20}};

// Before structured bindings — verbose
for (const auto &entry : ages) {
    cout << entry.first << ": " << entry.second << endl;
}

// With structured bindings — reads almost like natural language
for (const auto &[name, age] : ages) {
    cout << name << ": " << age << endl;
}

Structured Bindings with Structs

struct Point {
    int x, y;
};

Point p = {3, 4};
auto [px, py] = p;      // unpacks struct members directly
cout << px << " " << py;    // 3 4

Structured Bindings for Multi-Value Function Returns

pair<bool, string> validateInput(string input) {
    if (input.empty()) return {false, "Input cannot be empty"};
    return {true, "Valid"};
}

int main() {
    auto [isValid, message] = validateInput("");
    cout << isValid << " " << message;   // 0 Input cannot be empty
    return 0;
}
