Module 5.2 — Lambda Functions

A lambda expression is an anonymous, inline function — defined exactly where it's needed, without a separate named function declaration. Lambdas are used constantly with STL algorithms (Module 4.7) as custom comparators/predicates, and they solve function pointers' biggest limitation (Module 3.4): the ability to capture and use surrounding local variables.

1. Basic Syntax

auto greet = []() {
    cout << "Hello from a lambda!" << endl;
};

greet();  // calling it like a normal function — "Hello from a lambda!"

Anatomy of a Lambda

[capture](parameters) -> returnType {
    // body
};
PartMeaning
[capture]Which surrounding variables the lambda can access, and how (by value or reference)
(parameters)Same as a normal function's parameter list
-> returnTypeOptional — usually omitted, since the compiler deduces it from the return statement
{ body }The function's code

2. Parameters and Return Types

auto add = [](int a, int b) {
    return a + b;    // return type auto-deduced as int
};
cout << add(3, 4);      // 7

auto divide = [](double a, double b) -> double {   // explicit return type (rarely needed, but valid)
    if (b == 0) return 0.0;
    return a / b;
};
cout << divide(10, 4);      // 2.5

3. Capture Lists — The Core Concept

The capture list [...] determines which variables from the enclosing scope the lambda body can use, and whether it gets a copy or a reference to them. This is exactly what a plain function pointer cannot do.

Capture syntaxMeaning
[]Captures nothing — the lambda can only use its own parameters, not surrounding variables
[x]Captures x BY VALUE — a copy is made at the point the lambda is created
[&x]Captures x BY REFERENCE — the lambda sees live changes to the original x
[=]Captures ALL used surrounding variables BY VALUE, automatically
[&]Captures ALL used surrounding variables BY REFERENCE, automatically
[x, &y]Mixed — x by value, y by reference
[=, &y]Everything by value EXCEPT y, which is by reference
 
int x = 10;

auto byValue = [x]() {
    cout << x;   // uses the COPY captured when the lambda was created
};

auto byRef = [&x]() {
    cout << x;    // uses a REFERENCE — sees the CURRENT value of x, even if it changes later
};

x = 100;
byValue();   // 10 — captured copy, unaffected by the later change to x
byRef();       // 100 — reference sees the updated value

Capture-by-Value Is a Snapshot at Creation Time — Common Gotcha

vector<function<void()>> callbacks;

for (int i = 0; i < 3; i++) {
    callbacks.push_back([i]() { cout << i << " "; });  // captures a SEPARATE copy of i each iteration
}

for (auto &cb : callbacks) cb();  // 0 1 2 — each lambda remembers its own snapshot of i

// Compare with capturing by reference to the SAME loop variable (a classic bug pattern in other contexts):
int counter = 0;
auto incrementer = [&counter]() { counter++; };
incrementer(); incrementer(); incrementer();
cout << counter;  // 3 — all three calls affected the SAME shared counter, since it's captured by reference

Mutable Lambdas

By default, a value-captured variable inside a lambda is treated as const — the mutable keyword allows modifying the lambda's own internal copy (this does NOT affect the original variable):

int x = 10;

auto modifyCopy = [x]() mutable {
    x += 5;             // allowed ONLY because of `mutable` — modifies the lambda's OWN copy
    cout << x;             // 15
};

modifyCopy();
cout << x;                    // 10 — the ORIGINAL x is completely untouched; mutable only affects the copy

4. Lambdas with STL Algorithms — The Most Common Real-World Use

vector<int> v = {5, 2, 9, 1, 7};

// Custom sort comparator
sort(v.begin(), v.end(), [](int a, int b) {
    return a > b;   // descending order
});

// Custom predicate for count_if
int evenCount = count_if(v.begin(), v.end(), [](int x) {
    return x % 2 == 0;
});

// Using a CAPTURED variable as a threshold — this is exactly what a plain function pointer CANNOT easily do
int threshold = 5;
int aboveThreshold = count_if(v.begin(), v.end(), [threshold](int x) {
    return x > threshold;   // threshold captured from the surrounding scope
});

// for_each with a lambda
for_each(v.begin(), v.end(), [](int &x) {
    x *= 2;   // modifies elements in place — note the reference parameter
});

5. Lambdas vs Function Pointers vs Named Functions

AspectNamed functionFunction pointerLambda
Requires separate declarationYesYes (points to one)No — defined inline, exactly where used
Can capture surrounding variablesNo (only via globals or explicit parameters)NoYes — via the capture list, its key advantage
Typical useReusable, named logic used in multiple placesLegacy C-style callbacksOne-off logic, especially as STL algorithm arguments

6. Storing Lambdas — auto vs std::function

auto lam = [](int x) { return x * x; };   // auto — exact, lightweight, but the true type is compiler-internal/unnameable

#include <functional>
function<int(int)> f = [](int x) { return x * x; };  // std::function — a general "callable wrapper" type,
                                                          // useful when you need to store a lambda in a
                                                          // class member, a container, or pass it around
                                                          // as a named type (full depth in Module 5.7)
