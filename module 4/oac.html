Module 4.4 — Ordered Associative Containers

Associative containers store elements organized by key, automatically maintaining sorted order. Internally, both set and map are implemented as a self-balancing binary search tree (typically a Red-Black Tree), which is why every core operation runs in O(log n) — full internal detail in Module 4.8.

1. std::set

Stores unique elements in automatically sorted order. No duplicates are allowed — inserting an existing value is silently ignored.

#include <set>
using namespace std;

set<int> s;

s.insert(30);
s.insert(10);
s.insert(20);
s.insert(10);   // duplicate — silently ignored, set remains unchanged

for (int x : s) cout << x << " ";  // 10 20 30 — automatically sorted, ascending, no duplicates

cout << s.size();     // 3

s.erase(20);              // removes the value 20 → {10, 30}

cout << s.count(10);        // 1 — exists
cout << s.count(99);          // 0 — doesn't exist (count is 0 or 1 for a set, since duplicates aren't allowed)

auto it = s.find(30);            // returns an iterator to 30, or s.end() if not found
if (it != s.end()) {
    cout << "Found: " << *it;
}

Why find() Is Preferred Over Iterating Manually

set::find() uses the underlying tree structure to search in O(log n) — this is drastically faster than a manual linear scan (O(n)), which is exactly the advantage a set offers over, say, a plain vector for membership testing.

multiset — Allows Duplicates

#include <set>
multiset<int> ms;
ms.insert(10);
ms.insert(10);   // allowed — duplicates ARE permitted in a multiset
ms.insert(20);

cout << ms.count(10);  // 2

ms.erase(10);              // WARNING: erases ALL occurrences of 10, not just one!
// To erase only ONE occurrence:
auto it = ms.find(10);
if (it != ms.end()) ms.erase(it);  // erases just that single iterator's element

2. std::map

Stores key-value pairs, automatically sorted by key, with each key appearing exactly once (like a mathematical function — one key maps to exactly one value).

#include <map>
using namespace std;

map<string, int> ages;

ages["Vinit"] = 22;         // insert or update via operator[]
ages["Aman"] = 20;
ages["Priya"] = 21;

ages.insert({"Rahul", 23});   // alternative insertion syntax
ages.insert(make_pair("Neha", 19));

for (auto &entry : ages) {
    cout << entry.first << ": " << entry.second << endl;
}
// Automatically sorted BY KEY, alphabetically:
// Aman: 20
// Neha: 19
// Priya: 21
// Rahul: 23
// Vinit: 22

cout << ages["Vinit"];       // 22
cout << ages.count("Aman");    // 1 — exists
cout << ages.count("XYZ");       // 0 — doesn't exist

ages.erase("Priya");               // removes that key-value pair

Critical gotcha — operator[] auto-inserts on read!

map<string, int> ages = {{"Vinit", 22}};

cout << ages["Unknown"];     // prints 0, but ALSO SILENTLY INSERTS "Unknown" → 0 into the map!
cout << ages.size();            // 2 now — "Unknown" was added as a side effect of merely READING it

// This is one of the most common map-related interview traps.
// SAFE way to check existence WITHOUT accidentally inserting:
if (ages.find("Unknown") != ages.end()) {
    cout << "exists";
} else {
    cout << "does not exist";  // this runs — and crucially, does NOT insert anything
}

// Or equivalently, using count() (also does not insert):
if (ages.count("Unknown") > 0) { /* exists */ }

Iterating and Modifying

map<string, int> scores = {{"Vinit", 85}, {"Aman", 92}};

for (auto &entry : scores) {
    entry.second += 5;  // can modify the VALUE through the reference (the key stays const)
}

for (auto &entry : scores) {
    cout << entry.first << ": " << entry.second << endl;
}
// Vinit: 90
// Aman: 97

multimap — Allows Duplicate Keys

multimap<string, int> mm;
mm.insert({"Vinit", 85});
mm.insert({"Vinit", 90});  // allowed — same key can appear multiple times

for (auto &entry : mm) {
    cout << entry.first << ": " << entry.second << endl;
}
// Vinit: 85
// Vinit: 90
// NOTE: multimap has NO operator[] — because a key can map to multiple values, [] wouldn't make sense

3. Common Patterns

Frequency counting with map

string s = "programming";
map<char, int> freq;

for (char c : s) {
    freq[c]++;   // operator[]'s auto-insert behavior is actually USEFUL here:
                    // if c isn't in the map yet, it's inserted with value 0, then incremented to 1
}

for (auto &entry : freq) {
    cout << entry.first << ": " << entry.second << endl;
}

Checking for a value's presence before use

set<int> seen;
vector<int> nums = {1, 2, 2, 3, 1, 4};
vector<int> unique;

for (int n : nums) {
    if (seen.find(n) == seen.end()) {   // not seen before
        seen.insert(n);
        unique.push_back(n);
    }
}
// unique = {1, 2, 3, 4}

4. Ordered by Key — Range Queries with lower_bound/upper_bound

Because set/map maintain sorted order internally, they support efficient range operations directly as member functions (distinct from the standalone <algorithm> versions covered in Module 4.7): 

set<int> s = {10, 20, 30, 40, 50};

auto it1 = s.lower_bound(25);   // iterator to first element >= 25 → points to 30
auto it2 = s.upper_bound(30);     // iterator to first element > 30 → points to 40

cout << *it1 << " " << *it2;        // 30 40

Practice Questions

Conceptual

  1. Why does map::operator[] silently insert a default value when reading a non-existent key? What's the safe alternative for existence checks?
  2. What is the difference between set and multiset? Give an example where multiset::erase(value) could unexpectedly remove more elements than intended.
  3. Why does multimap not support operator[]?
  4. What is the time complexity of set::find(), and what internal data structure makes this possible?
  5. Explain why iterating over a map or set always produces elements in sorted order, without any explicit sort call.

Coding

  1. Write a program that reads a sentence and uses a map<string, int> to count the frequency of each word, then prints words alphabetically with their counts.
  2. Write a program that uses a set to remove duplicates from a vector while automatically sorting the result.
  3. Write a program that checks whether two arrays share any common elements, using a set for O(n log n) lookup instead of a brute-force O(n²) comparison.
  4. Write a program using a map<char,int> to check if two strings are anagrams of each other (compare frequency maps).
  5. Write a program that uses multimap<int, string> to group student names by their grade/score, then prints all students grouped by score in ascending order.
