Module 4.7 — Algorithms

The <algorithm> header provides a large library of generic, container-agnostic functions that operate on iterator ranges — meaning the same sort() call works identically whether you're sorting a vector, an array, or a deque. This section covers the algorithms most frequently used in interviews and everyday C++ code.

1. sort()

#include <algorithm>
using namespace std;

vector<int> v = {5, 2, 9, 1, 7};

sort(v.begin(), v.end());                    // ascending → {1, 2, 5, 7, 9}
sort(v.begin(), v.end(), greater<int>());       // descending → {9, 7, 5, 2, 1}

// Custom comparator with a lambda
sort(v.begin(), v.end(), [](int a, int b) {
    return a > b;   // return true if a should come BEFORE b
});

// Sorting a partial range — only the first 3 elements
sort(v.begin(), v.begin() + 3);

Complexity: O(n log n) — typically implemented as introsort (a hybrid of quicksort, heapsort, and insertion sort for small ranges).

Sorting a vector of pairs/custom objects

vector<pair<int,string>> students = {{85,"Vinit"}, {92,"Aman"}, {78,"Priya"}};

sort(students.begin(), students.end());  // sorts by .first automatically (lexicographic pair comparison)

sort(students.begin(), students.end(), [](pair<int,string> &a, pair<int,string> &b) {
    return a.second < b.second;   // custom: sort by NAME instead of marks
});

2. reverse()

vector<int> v = {1, 2, 3, 4, 5};
reverse(v.begin(), v.end());   // → {5, 4, 3, 2, 1} — in place, O(n)

string s = "hello";
reverse(s.begin(), s.end());     // → "olleh" — works on strings too, since they support iterators

3. find()

vector<int> v = {10, 20, 30, 40};

auto it = find(v.begin(), v.end(), 30);
if (it != v.end()) {
    cout << "Found at index: " << (it - v.begin());  // 2
} else {
    cout << "Not found";
}

Complexity: O(n) — find() is a linear scan, since it works on ANY iterator range (including unsorted ones) and has no way to skip ahead. For sorted data, binary_search (below) is dramatically faster.

4. count()

vector<int> v = {1, 2, 2, 3, 2, 4};
int c = count(v.begin(), v.end(), 2);
cout << c;   // 3 — number of times 2 appears

5. binary_search()

Requires the range to already be sorted — returns only true/false, not a position:

vector<int> v = {1, 3, 5, 7, 9, 11};   // MUST be sorted for binary_search to work correctly

cout << binary_search(v.begin(), v.end(), 7);    // true
cout << binary_search(v.begin(), v.end(), 4);       // false — 4 isn't present

// On UNSORTED data, binary_search gives UNDEFINED/INCORRECT results — always sort first!

Complexity: O(log n) — this is exactly why sorting first (O(n log n), one-time cost) is worth it if you need to perform many subsequent searches.

6. lower_bound() and upper_bound()

Also require sorted data. These return iterators (not booleans), pinpointing exact positions — extremely useful for counting occurrences, finding insertion points, or range queries. 

vector<int> v = {10, 20, 20, 20, 30, 40};

auto lb = lower_bound(v.begin(), v.end(), 20);   // iterator to FIRST element >= 20
auto ub = upper_bound(v.begin(), v.end(), 20);     // iterator to FIRST element > 20

cout << (lb - v.begin());    // 1 — index of first 20
cout << (ub - v.begin());      // 4 — index just past the last 20

int countOf20 = ub - lb;          // 3 — count of 20s, computed via iterator distance, without any loop!

// Finding an insertion point to keep a sorted vector sorted:
auto pos = lower_bound(v.begin(), v.end(), 25);
v.insert(pos, 25);   // inserts 25 in the correct sorted position

7. min_element() and max_element()

vector<int> v = {5, 2, 9, 1, 7};

auto minIt = min_element(v.begin(), v.end());
auto maxIt = max_element(v.begin(), v.end());

cout << *minIt << " " << *maxIt;      // 1 9
cout << (minIt - v.begin());                // 3 — INDEX of the minimum element

Complexity: O(n) — these work on unsorted data too, since they simply scan and track the extreme value (unlike binary_search/lower_bound, which require sorted input).

8. Other Frequently Used Algorithms

vector<int> v = {1, 2, 3, 4, 5};

// accumulate — sum (or custom fold) over a range (needs <numeric>)
#include <numeric>
int total = accumulate(v.begin(), v.end(), 0);          // 15 — sum, starting from 0
int product = accumulate(v.begin(), v.end(), 1, multiplies<int>()); // 120 — custom operation

// unique — removes CONSECUTIVE duplicates (requires sorted input for a "true" dedupe)
vector<int> v2 = {1, 1, 2, 2, 3, 1};
auto newEnd = unique(v2.begin(), v2.end());   // {1, 2, 3, 1, ?, ?} — logically removes CONSECUTIVE dupes only
v2.erase(newEnd, v2.end());                       // must erase the leftover "garbage" tail — {1, 2, 3, 1}

// swap — exchanges two values
int a = 5, b = 10;
swap(a, b);    // a=10, b=5

// all_of / any_of / none_of — check a condition across a range (needs a predicate)
bool allPositive = all_of(v.begin(), v.end(), [](int x) { return x > 0; });
bool anyEven = any_of(v.begin(), v.end(), [](int x) { return x % 2 == 0; });

// count_if — count elements satisfying a condition
int evenCount = count_if(v.begin(), v.end(), [](int x) { return x % 2 == 0; });

// for_each — apply a function to every element
for_each(v.begin(), v.end(), [](int &x) { x *= 2; }); // doubles every element in place

Practice Questions

Conceptual

  1. Why is binary_search() undefined/unreliable on unsorted data, while find() works correctly regardless of ordering?
  2. Explain what unique() actually does — why is a subsequent erase() call typically required afterward to fully "clean up" the container?
  3. Why is it worth paying the O(n log n) cost of sorting upfront if you plan to perform many subsequent lookups with binary_search/lower_bound?
  4. What is the difference between lower_bound() and upper_bound() when searching for a value that appears multiple times?

Coding

  1. Write a program that sorts a vector<pair<int,string>> of (score, name) by score descending, then by name ascending for ties, using a custom lambda comparator.
  2. Write a program that uses lower_bound/upper_bound to count how many times a given value appears in a sorted array, without any explicit loop.
  3. Write a program using accumulate to compute both the sum and the product of a vector of integers.
  4. Write a program that removes duplicates from an unsorted vector by first sorting it, then applying unique + erase.
  5. Write a program that uses count_if to count how many elements in a vector are prime numbers (using a helper isPrime() function as the predicate).
