Module 4.3 — Container Adaptors

Container adaptors don't implement their own storage — instead, they wrap an existing sequence container (by default, deque) and restrict the interface to a specific access pattern (LIFO, FIFO, or priority-based). This restriction is the whole point: it makes the intended usage pattern explicit and prevents misuse.

1. std::stack — LIFO (Last In, First Out)

A stack only allows access to the top element — think of a stack of plates: you can only add to or remove from the top. 

#include <stack>
using namespace std;

stack<int> s;

s.push(10);       // → top: 10
s.push(20);         // → top: 20
s.push(30);           // → top: 30

cout << s.top();          // 30 — only the top element is accessible
s.pop();                     // removes 30 (pop() does NOT return the value — unlike some other languages!)
cout << s.top();               // 20

cout << s.size();                // 2
cout << s.empty();                 // false

Common gotcha: pop() returns void — you must call top() to get the value BEFORE calling pop() to remove it:

int val = s.top();  // get the value first
s.pop();               // then remove it — this is TWO separate steps in C++

Common Use Cases for Stack

  • Balanced parentheses checking
  • Undo/redo functionality
  • DFS traversal (iterative version — Module 6.8)
  • Expression evaluation (infix/postfix conversion)
  • Function call stack simulation (recursion — Module 1.3)
// Classic example: balanced parentheses check
bool isBalanced(string s) {
    stack<char> st;
    for (char c : s) {
        if (c == '(' || c == '[' || c == '{') {
            st.push(c);
        } else {
            if (st.empty()) return false;
            char top = st.top();
            st.pop();
            if ((c == ')' && top != '(') ||
                (c == ']' && top != '[') ||
                (c == '}' && top != '{')) {
                return false;
            }
        }
    }
    return st.empty();  // must be empty — every open must be matched
}

2. std::queue — FIFO (First In, First Out)

A queue only allows insertion at the back and removal from the front — think of a real-world line/queue: the first person to join is the first to leave. 

#include <queue>
using namespace std;

queue<int> q;

q.push(10);     // → back: 10, front: 10
q.push(20);       // → back: 20, front: 10
q.push(30);         // → back: 30, front: 10

cout << q.front();      // 10 — first element added
cout << q.back();          // 30 — most recently added

q.pop();                      // removes from the FRONT (10) — → front is now 20
cout << q.front();               // 20

cout << q.size();                   // 2
cout << q.empty();                    // false

Common Use Cases for Queue

  • BFS traversal (Module 6.8) — the canonical use case
  • Task scheduling / processing in arrival order
  • Buffering / streaming data

3. std::priority_queue — Always Access the "Highest Priority" Element

A priority queue keeps elements ordered such that the largest element (by default) is always accessible at the top — internally implemented as a binary heap (full internals covered in Module 4.8 and Module 6.7). 

#include <queue>
using namespace std;

priority_queue<int> pq;   // MAX-heap by default

pq.push(30);
pq.push(10);
pq.push(50);
pq.push(20);

cout << pq.top();   // 50 — the LARGEST element, regardless of insertion order

while (!pq.empty()) {
    cout << pq.top() << " ";  // 50 30 20 10 — always retrieves in descending order
    pq.pop();
}

Min-Heap Variant

priority_queue<int, vector<int>, greater<int>> minPQ;   // MIN-heap

minPQ.push(30);
minPQ.push(10);
minPQ.push(50);

cout << minPQ.top();  // 10 — the SMALLEST element now on top

while (!minPQ.empty()) {
    cout << minPQ.top() << " ";  // 10 30 50 — ascending order
    minPQ.pop();
}

Reading the min-heap declaration: the three template parameters are priority_queue<ValueType, UnderlyingContainer, ComparisonFunction>. greater<int> flips the ordering so that "greater" elements are treated as lower priority — counterintuitively producing a min-heap.

Custom Comparator (e.g., priority queue of pairs)

// Min-heap of pairs, ordered by .first
priority_queue<pair<int,int>, vector<pair<int,int>>, greater<pair<int,int>>> pq;

pq.push({5, 100});
pq.push({2, 200});
pq.push({8, 300});

cout << pq.top().first;  // 2 — smallest .first value on top

Custom Comparator with a Lambda (C++11+)

auto cmp = [](int a, int b) { return a > b; };  // reversed logic → produces a min-heap
priority_queue<int, vector<int>, decltype(cmp)> pq(cmp);

pq.push(30); pq.push(10); pq.push(50);
cout << pq.top();  // 10

Common Use Cases for Priority Queue

  • Top-K element problems (Module 6.7)
  • Dijkstra's shortest path algorithm (Module 6.8)
  • Task scheduling by priority
  • Merging K sorted lists

4. Adaptors Have a Restricted Interface — On Purpose

None of these three containers support iteration with a range-based for loop, indexing with [], or arbitrary-position access — because that would defeat their entire purpose of enforcing a specific access discipline. 

stack<int> s;
s.push(1); s.push(2);
// for (int x : s) { }   // COMPILE ERROR — stack has no begin()/end(), by design
// cout << s[0];            // COMPILE ERROR — no operator[]

If you need to inspect all elements without destroying the container's order, you generally have to pop elements into a temporary structure (or, better, reconsider whether an adaptor is the right container for that use case).

5. Underlying Container Choice

Each adaptor wraps another container by default, but this is configurable via a template parameter:

AdaptorDefault underlying container
stackdeque
queuedeque
priority_queuevector
 
stack<int, vector<int>> s;   // explicitly use vector instead of the default deque

Practice Questions

Conceptual

  1. Why don't stack, queue, and priority_queue support range-based for loops or indexing?
  2. Explain why greater<int> as the comparator produces a MIN-heap rather than a max-heap — this confuses many people at first.
  3. What are container adaptors built on top of, by default, for each of the three types?
  4. Give one real-world algorithmic scenario each for stack, queue, and priority_queue where that specific structure is the natural choice.

Coding

  1. Write a function that checks whether a given string of brackets (()[]{}) is balanced, using a stack.
  2. Write a program that reverses a queue using only a stack as auxiliary storage (no other container allowed).
  3. Write a program that finds the K largest elements in an array using a priority_queue (min-heap of size K approach).
  4. Write a program that simulates a simple task scheduler: tasks are pushed with a priority number, and processed by popping the highest-priority task each time using a priority_queue<pair<int,string>>.
  5. Write a function using a stack to evaluate a postfix expression (e.g., "5 3 + 2 *" → 16).
