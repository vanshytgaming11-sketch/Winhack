Module 4.6 — Iterators

An iterator is an object that acts like a generalized pointer, allowing traversal through a container's elements without exposing the container's internal implementation. Iterators are the glue that lets STL algorithms (Module 4.7) work uniformly across completely different container types.

1. begin() and end()

vector<int> v = {10, 20, 30, 40, 50};

vector<int>::iterator it = v.begin();   // points to the FIRST element
cout << *it;                                // 10

it = v.end();                                 // points ONE PAST the LAST element (NOT the last element itself!)
// *it would be UNDEFINED BEHAVIOR — end() is a sentinel, not a valid dereferenceable position

Using auto to simplify the verbose iterator type (standard practice):

auto it = v.begin();   // much cleaner than vector<int>::iterator it = v.begin();

The Standard Iteration Idiom

vector<int> v = {10, 20, 30, 40, 50};

for (auto it = v.begin(); it != v.end(); ++it) {
    cout << *it << " ";
}
// 10 20 30 40 50

Why != and not <? Not all iterators support relational comparison (<) — a list iterator, for instance, only supports ==/!= and increment, since "less than" has no meaningful definition for a linked list's non-contiguous nodes. Using != works universally across every container type; < only works for random-access iterators like vector's.

2. Iterator Movement

vector<int> v = {10, 20, 30, 40, 50};

auto it = v.begin();
++it;              // pre-increment — moves to next element — prefer this over it++ for efficiency
cout << *it;         // 20

it--;                  // moves back one position
cout << *it;             // 10

auto lastIt = v.end();
--lastIt;                   // moves BACK from end() to point at the actual LAST element
cout << *lastIt;              // 50 — this is the standard idiom for accessing the last element via iterator

3. Categories of Iterators

Different containers support different levels of iterator capability, forming a hierarchy from most to least restrictive:

CategorySupportsExample containers
Input iteratorSingle-pass read, ++Stream iterators
Output iteratorSingle-pass write, ++Insert iterators
Forward iteratorMulti-pass read/write, ++forward_list, unordered_map/unordered_set
Bidirectional iteratorForward + -- (move backward)list, map, set
Random-access iteratorBidirectional + jump by any offset (it + n), full comparison (<, >)vector, deque, array
 
vector<int> v = {10, 20, 30, 40, 50};
auto vit = v.begin();
vit = vit + 3;          // OK — vector has RANDOM-ACCESS iterators, supports arbitrary jumps
cout << *vit;             // 40

list<int> l = {10, 20, 30, 40, 50};
auto lit = l.begin();
// lit = lit + 3;        // COMPILE ERROR — list only has BIDIRECTIONAL iterators, no `+` jump support
++lit; ++lit; ++lit;        // must advance one step at a time instead
cout << *lit;                 // 40

4. advance()

std::advance(it, n) (from <iterator>) moves an iterator forward by n positions, working correctly regardless of iterator category — for random-access iterators it's O(1) (uses + internally), but for bidirectional/forward iterators it performs n individual ++ steps internally, making it O(n). 

#include <iterator>

list<int> l = {10, 20, 30, 40, 50};
auto it = l.begin();
advance(it, 2);        // moves forward 2 positions — works even though list lacks `+`
cout << *it;              // 30

advance(it, -1);            // negative values move BACKWARD (works for bidirectional+ iterators)
cout << *it;                  // 20

5. Iterator vs Pointer

Iterators were deliberately designed to mimic pointer syntax — this is intentional, since raw pointers ARE valid random-access iterators for plain arrays:

AspectPointerIterator
Works withRaw arrays, or explicit address-of useAny STL container, generically
Type safetyCan point anywhere — less safeBound to the specific container's element type
AbstractionExposes raw memory addresses directlyHides internal representation (e.g., tree node internals for map)
Arithmetic supportAlways supported (raw memory)Depends on category — only random-access iterators support full arithmetic
 
int arr[5] = {1, 2, 3, 4, 5};
int *p = arr;          // a raw pointer used exactly like an iterator
cout << *(p + 2);         // 3 — works because arrays have contiguous memory, just like vector

vector<int> v = {1, 2, 3, 4, 5};
auto it = v.begin();
cout << *(it + 2);           // 3 — vector's iterator IS effectively a pointer under the hood (or behaves like one)

6. Const Iterators & Reverse Iterators

vector<int> v = {10, 20, 30};

for (auto it = v.cbegin(); it != v.cend(); ++it) {   // const_iterator — read-only, cannot modify *it
    cout << *it << " ";
    // *it = 99;    // COMPILE ERROR
}

for (auto it = v.rbegin(); it != v.rend(); ++it) {   // reverse_iterator — traverses BACKWARD
    cout << *it << " ";
}
// 30 20 10 — note: ++ on a reverse_iterator actually moves it BACKWARD through the container

7. Iterator Invalidation (critical, ties back to Module 4.1)

Certain container operations invalidate existing iterators — using an invalidated iterator afterward is undefined behavior. This varies by container:

ContainerInvalidating operations
vectorAny insertion that triggers reallocation invalidates ALL iterators; erase invalidates iterators from that point onward
dequeInsertion/erasure at either end may invalidate all iterators (implementation-dependent)
listOnly the iterator to the specifically erased element is invalidated — all others remain valid (a key advantage)
map/setOnly the iterator to the specifically erased element is invalidated
 
vector<int> v = {1, 2, 3, 4, 5};
for (auto it = v.begin(); it != v.end(); ++it) {
    if (*it == 3) {
        v.erase(it);   // DANGEROUS — erase() invalidates `it`; using it (even in the loop's ++it) is undefined behavior
    }
}

// CORRECT pattern — erase() returns a valid iterator to the element AFTER the one removed
for (auto it = v.begin(); it != v.end(); ) {
    if (*it == 3) {
        it = v.erase(it);   // reassign it to erase()'s return value
    } else {
        ++it;
    }
}

Practice Questions

Conceptual

  1. Why is it != v.end() preferred over it < v.end() as the general iteration condition across all container types?
  2. Explain the difference between forward, bidirectional, and random-access iterators, with one example container for each.
  3. Why does advance(it, n) run in O(1) for a vector but O(n) for a list?
  4. Explain iterator invalidation: why is erasing from a vector while iterating more dangerous than erasing from a list while iterating?
  5. What is the relationship between raw pointers and iterators — why can a raw pointer be used as a valid iterator over a plain array?

Coding

  1. Write a program that uses iterators (not indices) to print a vector<int> in both forward and reverse order.
  2. Write a program that correctly removes all even numbers from a vector<int> while iterating, using the erase()-returns-next-iterator pattern.
  3. Write a program using list<int> and advance() to access and print the middle element of the list.
  4. Write a program that uses a set<int>::iterator to print all elements strictly between two given values (using lower_bound/upper_bound from Module 4.4).
