Module 4.1 — Sequence Containers

Sequence containers store elements in a strict linear order, where each element's position is independent of its value (unlike associative containers, covered in 4.4/4.5, which order elements by key). The three most important sequence containers are vector, deque, and list — each with different internal storage strategies and performance trade-offs.

1. std::vector

A dynamic array — contiguous memory that automatically resizes (grows) as elements are added. This is by far the most commonly used STL container, and usually the default choice unless a specific access pattern favors another container.

Declaration & Initialization

#include <vector>
using namespace std;

vector<int> v1;                     // empty vector
vector<int> v2(5);                    // 5 elements, all default-initialized to 0
vector<int> v3(5, 10);                  // 5 elements, all initialized to 10
vector<int> v4 = {1, 2, 3, 4, 5};         // initializer list
vector<int> v5(v4);                        // copy of v4
vector<vector<int>> grid(3, vector<int>(4, 0)); // 3x4 2D grid, all zeros

Core Operations

vector<int> v = {10, 20, 30};

v.push_back(40);          // adds to the end → {10, 20, 30, 40}
v.pop_back();               // removes from the end → {10, 20, 30}

cout << v[0];                  // 10 — no bounds checking (undefined behavior if out of range)
cout << v.at(0);                 // 10 — bounds-checked, throws std::out_of_range if invalid
cout << v.front();                 // 10 — first element
cout << v.back();                    // 30 — last element

cout << v.size();                       // 3 — current number of elements
cout << v.empty();                        // false (0)
cout << v.capacity();                       // internal allocated capacity (≥ size, implementation-dependent)

v.insert(v.begin() + 1, 15);                   // insert 15 at index 1 → {10, 15, 20, 30}
v.erase(v.begin() + 1);                           // remove element at index 1 → {10, 20, 30}
v.clear();                                          // removes all elements → size 0

vector<int> v2 = {1, 2, 3};
v2.resize(5);                                          // → {1, 2, 3, 0, 0}
v2.resize(2);                                            // → {1, 2} (truncates)

Traversal

vector<int> v = {1, 2, 3, 4, 5};

for (int i = 0; i < v.size(); i++) cout << v[i] << " ";     // indexed
for (int x : v) cout << x << " ";                              // range-based
for (auto it = v.begin(); it != v.end(); it++) cout << *it << " "; // iterator-based (Module 4.6)

How vector Grows Internally (interview-critical, previewed here, full detail in 4.8)

When a vector exceeds its current capacity, it doesn't grow by one — it allocates a new, larger block (typically double the current capacity), copies/moves all existing elements into it, and frees the old block. This is why push_back has amortized O(1) time complexity: most calls are O(1), but occasionally one call costs O(n) to reallocate — averaged over many calls, the cost per call is still constant. 

vector<int> v;
for (int i = 0; i < 10; i++) {
    v.push_back(i);
    cout << "size=" << v.size() << " capacity=" << v.capacity() << endl;
}
// Typical output pattern (exact growth factor is implementation-defined):
// size=1 capacity=1
// size=2 capacity=2
// size=3 capacity=4
// size=4 capacity=4
// size=5 capacity=8
// ... capacity roughly doubles each time it's exceeded

Reallocation invalidates iterators/pointers/references to existing elements — a very common bug source:

vector<int> v = {1, 2, 3};
int *p = &v[0];
v.push_back(4);       // may trigger reallocation
cout << *p;              // UNDEFINED BEHAVIOR if reallocation occurred — p may point to freed memory

If the final size is known in advance, use v.reserve(n) to pre-allocate capacity and avoid repeated reallocations:

vector<int> v;
v.reserve(1000);   // allocates capacity for 1000 elements up front — subsequent push_backs won't reallocate
for (int i = 0; i < 1000; i++) v.push_back(i); // no reallocation occurs during this loop

2. std::deque

Short for "double-ended queue," a deque supports efficient insertion and removal at both ends — unlike vector, which is only efficient at the back. 

#include <deque>
using namespace std;

deque<int> dq = {2, 3, 4};

dq.push_back(5);      // → {2, 3, 4, 5}
dq.push_front(1);       // → {1, 2, 3, 4, 5}  — O(1), unlike vector's O(n) for front insertion

dq.pop_back();             // → {1, 2, 3, 4}
dq.pop_front();               // → {2, 3, 4}

cout << dq[0] << " " << dq.front() << " " << dq.back(); // supports [] just like vector

for (int x : dq) cout << x << " "; // range-based traversal works the same way

Internal structure: a deque is NOT one contiguous block like a vector — it's typically implemented as a sequence of fixed-size blocks (chunks), with an internal map (array of pointers) tracking those blocks. This is what allows O(1) insertion at both ends without shifting all existing elements, at the cost of slightly slower random access than vector (one extra level of indirection) and non-contiguous memory (bad for cache locality compared to vector).

vector vs deque — When to Use Which

Operationvectordeque
Push/pop at backO(1) amortizedO(1)
Push/pop at frontO(n) — must shift everythingO(1)
Random access [i]O(1), very fast (contiguous, cache-friendly)O(1), but slightly slower (indirection)
Memory layoutSingle contiguous blockMultiple non-contiguous blocks
Best forMostly back insertions, frequent random accessInsertions/removals at both ends (e.g., sliding window)

3. std::list

A doubly linked list — every element is a separately allocated node containing pointers to the previous and next nodes. Unlike vector/deque, elements are NOT stored contiguously or accessible by index at all. 

#include <list>
using namespace std;

list<int> l = {2, 3, 4};

l.push_back(5);       // → {2, 3, 4, 5}
l.push_front(1);        // → {1, 2, 3, 4, 5}

l.pop_back();              // → {1, 2, 3, 4}
l.pop_front();                // → {2, 3, 4}

// l[0];    // COMPILE ERROR — list does NOT support random access / operator[]

cout << l.front() << " " << l.back(); // front/back still work — O(1)

for (int x : l) cout << x << " ";       // range-based traversal — the ONLY practical way to iterate

Efficient Insertion/Removal Anywhere (list's key advantage)

list<int> l = {1, 2, 4, 5};

auto it = l.begin();
advance(it, 2); // move iterator to point at the element '4' (index 2)

l.insert(it, 3);   // insert 3 BEFORE the position it points to → {1, 2, 3, 4, 5}
                      // this is O(1) once you HAVE the iterator — no shifting of other elements!

l.erase(it);          // removes the element the iterator points to (4) → {1, 2, 3, 5}

This is list's core advantage: once you have an iterator to a position, inserting or removing there is O(1) — no elements need to shift, because you're just relinking a few pointers. Compare this to vector, where inserting/removing in the middle is O(n) because all subsequent elements must shift over.

vector vs list — When to Use Which

Operationvectorlist
Random access [i]O(1)Not supported — would require O(n) traversal

4. Choosing the Right Sequence Container — Summary

  • Default to vector unless you have a specific reason not to — it's the most cache-friendly and generally fastest in practice for most workloads.
  • Use deque when you need efficient insertion/removal at both the front and back (e.g., implementing a sliding window, or a queue that also needs front access).
  • Use list only when you need frequent insertion/removal in the middle of the sequence AND rarely need random access — this is a fairly narrow use case in practice.

Practice Questions

Conceptual

  1. Explain why push_back on a vector is described as "amortized O(1)" rather than simply "O(1)."
  2. Why does a vector reallocation invalidate existing pointers/references/iterators, while a list insertion does not invalidate other elements' iterators?
  3. Why can't std::list support operator[] the way vector and deque can?
  4. Explain the internal structural difference between vector and deque that allows deque to support O(1) front insertion.
  5. When would you choose list over vector? Give a concrete scenario.

Coding

  1. Write a program that reads n integers into a vector, then removes all even numbers from it in place.
  2. Write a program using a deque to simulate a simple browser history: push_back for visiting a new page, pop_back for going back, and push_front/pop_front to demonstrate front operations.
  3. Write a program using std::list that inserts elements at specific positions using iterators, and removes all elements with a given value.
  4. Write a program that demonstrates the difference in capacity() growth of a vector with and without calling reserve() beforehand, printing capacity after each push_back for both cases.
