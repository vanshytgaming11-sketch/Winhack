Module 6.7 — Heaps

Module 4.3 introduced priority_queue as the STL's ready-made heap, and Module 4.8 covered its array-based internal structure. This module focuses on the algorithmic top-K pattern — the most common way heaps appear in interviews — plus how to implement heap operations manually, which interviewers sometimes ask for directly.

1. Heap Property Recap

TypePropertyRoot holds
Max-heapEvery parent ≥ both childrenThe maximum element
Min-heapEvery parent ≤ both childrenThe minimum element

Note: a heap is NOT fully sorted — it only guarantees the parent/child ordering, not that siblings or cousins are ordered relative to each other. This weaker guarantee is exactly what makes heap operations faster than maintaining a fully sorted structure.

2. Manual Heap Operations (Array-Based)

Recap from Module 4.8: for a node at index i in a 0-indexed array, its parent is at (i-1)/2, and its children are at 2i+1 and 2i+2.

Push (Insert) — "Bubble Up"

class MinHeap {
    public:
        vector<int> heap;

        void push(int val) {
            heap.push_back(val);              // add at the end
            int i = heap.size() - 1;
            while (i > 0 && heap[(i-1)/2] > heap[i]) {   // bubble up while parent is larger
                swap(heap[(i-1)/2], heap[i]);
                i = (i-1)/2;
            }
        }
};
// O(log n) — the new element can bubble up at most the height of the tree, which is O(log n)

Pop (Remove Min/Max) — "Sift Down"

void pop() {
    heap[0] = heap.back();     // move the LAST element to the root
    heap.pop_back();
    int i = 0;

    while (true) {
        int left = 2*i + 1, right = 2*i + 2, smallest = i;

        if (left < heap.size() && heap[left] < heap[smallest]) smallest = left;
        if (right < heap.size() && heap[right] < heap[smallest]) smallest = right;

        if (smallest == i) break;   // heap property restored — stop

        swap(heap[i], heap[smallest]);
        i = smallest;
    }
}
// O(log n) — the moved element sifts down at most the height of the tree

3. Top-K Elements Pattern

The most frequently tested heap application: finding the K largest (or smallest) elements from a stream or array, in better than O(n log n) (full sort) time.

K Largest Elements — Using a MIN-Heap of Size K (the key insight)

vector<int> kLargest(vector<int> &arr, int k) {
    priority_queue<int, vector<int>, greater<int>> minHeap;   // min-heap, from Module 4.3

    for (int x : arr) {
        minHeap.push(x);
        if (minHeap.size() > k) {
            minHeap.pop();   // remove the SMALLEST — keeps only the k LARGEST seen so far
        }
    }

    vector<int> result;
    while (!minHeap.empty()) {
        result.push_back(minHeap.top());
        minHeap.pop();
    }
    return result;
}
// O(n log k) time — better than O(n log n) full sort when k is much smaller than n
// O(k) space — the heap never holds more than k elements at once

Why a MIN-heap for the K LARGEST (this trips people up at first): the heap always holds the K largest elements seen so far, and its root (the minimum of that set) is exactly the "weakest link" — the first candidate to evict when a new, larger element arrives. Using a max-heap instead would put the largest element at the top, giving no easy way to identify the smallest of the top-K to evict.

K Closest Points to Origin (a common variant)

vector<vector<int>> kClosest(vector<vector<int>> &points, int k) {
    // MAX-heap of size k, ordered by squared distance — evicts the FARTHEST point when full
    priority_queue<pair<int, vector<int>>> maxHeap;

    for (auto &p : points) {
        int dist = p[0]*p[0] + p[1]*p[1];
        maxHeap.push({dist, p});
        if (maxHeap.size() > k) {
            maxHeap.pop();   // remove the FARTHEST
        }
    }

    vector<vector<int>> result;
    while (!maxHeap.empty()) {
        result.push_back(maxHeap.top().second);
        maxHeap.pop();
    }
    return result;
}
// O(n log k) time — the mirror-image logic of kLargest: use a MAX-heap when you want the K SMALLEST

4. Kth Largest Element in a Stream (heap that persists across calls)

class KthLargest {
    priority_queue<int, vector<int>, greater<int>> minHeap;
    int k;

    public:
        KthLargest(int k, vector<int> &nums) : k(k) {
            for (int n : nums) add(n);
        }

        int add(int val) {
            minHeap.push(val);
            if (minHeap.size() > k) minHeap.pop();
            return minHeap.top();   // the Kth largest is always the min of a size-k min-heap
        }
};
// Each add() call is O(log k) — much better than re-sorting the entire stream on every insertion

5. Merging K Sorted Lists (classic heap application)

// Using the pair-comparator pattern from Module 4.3
ListNode* mergeKLists(vector<ListNode*> &lists) {
    auto cmp = [](ListNode *a, ListNode *b) { return a->val > b->val; };   // min-heap by node value
    priority_queue<ListNode*, vector<ListNode*>, decltype(cmp)> pq(cmp);

    for (ListNode *node : lists) {
        if (node) pq.push(node);
    }

    ListNode dummy(0);
    ListNode *tail = &dummy;

    while (!pq.empty()) {
        ListNode *smallest = pq.top();
        pq.pop();
        tail->next = smallest;
        tail = tail->next;

        if (smallest->next) pq.push(smallest->next);
    }

    return dummy.next;
}
// O(N log k) time, where N = total number of nodes across all lists, k = number of lists —
// far better than the O(N log N) of collecting everything and sorting from scratch

6. Heap vs Sorting — When to Choose Which

ScenarioBetter choiceWhy
Need only the top K out of N elementsHeap of size KO(n log k) < O(n log n) when k << n
Need ALL elements in sorted orderFull sortHeap offers no advantage if you need every element ordered anyway
Elements arrive as a continuous streamHeap (persists across insertions)Re-sorting from scratch on every new element would be far more expensive
Need the current min/max repeatedly, with insertions in betweenHeapO(log n) insert/extract vs. re-scanning O(n) each time

Practice Questions

Conceptual

  1. Explain why finding the K largest elements uses a MIN-heap rather than a MAX-heap — many people get this backward at first.
  2. Why is the top-K heap approach O(n log k) rather than O(n log n), and when does this actually matter in practice?
  3. Explain why merging K sorted lists with a heap achieves O(N log k) instead of O(N log N).
  4. In what scenario would a full sort be preferable to maintaining a heap, even though a heap has faster insertion?

Coding

  1. Implement a max-heap manually (push and pop, array-based, no STL priority_queue) and test it by heap-sorting an array.
  2. Write a function to find the K most frequent elements in an array, combining a frequency map (Module 6.5) with a heap of size K.
  3. Write a class MedianFinder that supports adding numbers one at a time and finding the running median efficiently, using TWO heaps (a max-heap for the lower half, a min-heap for the upper half).
  4. Write a function to reorganize a string so that no two adjacent characters are the same, using a max-heap ordered by character frequency.
