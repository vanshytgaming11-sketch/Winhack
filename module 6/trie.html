Module 6.11 — Trie

A trie (pronounced "try," from retrieval) is a tree-like structure specialized for storing and querying strings, where each path from the root spells out a prefix. Tries make prefix-based operations — "does any word start with this prefix," autocomplete, spell-checking — dramatically faster than scanning a list of strings.

1. Trie Structure

Each node represents a single character position and holds pointers to its possible next characters (commonly an array of 26 for lowercase English letters, or a hash map for a larger/sparser alphabet), plus a flag marking whether a complete word ends at that node. 

class TrieNode {
    public:
        TrieNode *children[26];   // one slot per lowercase letter 'a'-'z'
        bool isEndOfWord;

        TrieNode() : isEndOfWord(false) {
            for (int i = 0; i < 26; i++) children[i] = nullptr;
        }
};

2. Insert

class Trie {
    public:
        TrieNode *root;

        Trie() {
            root = new TrieNode();
        }

        void insert(string word) {
            TrieNode *curr = root;
            for (char c : word) {
                int idx = c - 'a';   // maps 'a'->0, 'b'->1, ..., 'z'->25
                if (curr->children[idx] == nullptr) {
                    curr->children[idx] = new TrieNode();   // create the path if it doesn't exist yet
                }
                curr = curr->children[idx];
            }
            curr->isEndOfWord = true;   // mark the final node as a complete word
        }
};
// O(L) time, where L = length of the word being inserted — independent of how many
// words are already in the trie

3. Search (Exact Word)

bool search(string word) {
    TrieNode *curr = root;
    for (char c : word) {
        int idx = c - 'a';
        if (curr->children[idx] == nullptr) return false;   // path doesn't exist — word isn't present
        curr = curr->children[idx];
    }
    return curr->isEndOfWord;   // path exists, but MUST also be marked as a complete word, not just a prefix
}
// O(L) time — L = length of the search word

Critical detail — isEndOfWord matters: if the trie contains "apple" but not "app", searching for "app" must return false even though the path a→p→p exists — because that path is only a prefix of "apple," not a complete inserted word itself. This is exactly why the flag is checked, not just path existence.

4. StartsWith (Prefix Check)

bool startsWith(string prefix) {
    TrieNode *curr = root;
    for (char c : prefix) {
        int idx = c - 'a';
        if (curr->children[idx] == nullptr) return false;
        curr = curr->children[idx];
    }
    return true;   // path exists — SOME word in the trie starts with this prefix
                      // (no isEndOfWord check needed here, unlike search())
}
// O(L) time — the entire reason a trie beats a plain list of strings for this exact
// operation: checking "does any string start with X" against N strings of length L
// naively costs O(N*L), but a trie answers it in O(L), REGARDLESS of how many words are stored

5. Full Working Example

int main() {
    Trie trie;
    trie.insert("apple");

    cout << trie.search("apple");     // true — exact word exists
    cout << trie.search("app");         // false — "app" was never explicitly inserted as a complete word
    cout << trie.startsWith("app");        // true — "apple" starts with "app"

    trie.insert("app");
    cout << trie.search("app");               // true — now it's ALSO been inserted as its own complete word
    return 0;
}

6. Word Dictionary with Wildcard Search (a common extension)

A frequent follow-up: support a . wildcard that can match ANY single character, requiring backtracking-style search (Module 6.9) through the trie.

bool searchWithWildcard(TrieNode *node, string &word, int index) {
    if (node == nullptr) return false;
    if (index == word.length()) return node->isEndOfWord;

    char c = word[index];
    if (c == '.') {
        // Wildcard — try EVERY possible child, succeed if ANY path leads to a match
        for (int i = 0; i < 26; i++) {
            if (searchWithWildcard(node->children[i], word, index + 1)) {
                return true;
            }
        }
        return false;
    } else {
        return searchWithWildcard(node->children[c - 'a'], word, index + 1);
    }
}
// O(26^m) worst case, where m = number of wildcard characters — degrades toward
// brute force when wildcards dominate, but performs like normal O(L) trie search
// when few or no wildcards are present

7. Why a Trie Over a Hash Set of Strings?

OperationHash set of stringsTrie
Exact word searchO(L) average (hashing the whole string)O(L)
"Does any word start with prefix X?"O(N*L) — must check every stored stringO(L) — independent of how many words are stored
Autocomplete (list all words with a prefix)O(N*L) scan, then filterO(L) to reach the prefix node, then traverse just that subtree
MemoryGenerally lower — no shared structureHigher — but SHARES memory across common prefixes (e.g., "app", "apple", "application" share the "app" path)

Practice Questions

Conceptual

  1. Explain why search() must check isEndOfWord while startsWith() does not, even though both traverse the trie the same way.
  2. Why is a trie's prefix-checking operation O(L) regardless of how many words are stored, while a hash set requires scanning all stored words for the same check?
  3. What memory trade-off does a trie make compared to a hash set of strings, and why does it still often win for prefix-heavy workloads?
  4. Why does wildcard search potentially degrade to O(26^m) — what specifically causes the exponential blowup?

Coding

  4. Write a function using a trie to determine if a given string can be segmented into a sequence of dictionary words (word break problem), combining trie lookup with DP (Module 6.10) memoization.
