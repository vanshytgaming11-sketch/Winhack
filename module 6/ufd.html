Module 6.12 — Union-Find / DSU

Disjoint Set Union (DSU), also called Union-Find, is a data structure that tracks a collection of disjoint (non-overlapping) sets, supporting two operations extremely efficiently: determining which set an element belongs to (find), and merging two sets together (union). It's the standard tool for connectivity and grouping problems on graphs.

1. The Core Idea — Parent Pointers

Each element points to a "parent" — following parent pointers repeatedly eventually reaches a root, which represents that entire set. Two elements are in the same set if and only if they share the same root. 

class DSU {
    public:
        vector<int> parent;

        DSU(int n) {
            parent.resize(n);
            for (int i = 0; i < n; i++) {
                parent[i] = i;   // initially, every element is its OWN parent — n separate sets
            }
        }

        int find(int x) {
            if (parent[x] == x) return x;   // x IS the root of its set
            return find(parent[x]);            // otherwise, follow the parent pointer up
        }

        void unite(int x, int y) {
            int rootX = find(x);
            int rootY = find(y);
            if (rootX != rootY) {
                parent[rootX] = rootY;   // merge: make one root point to the other
            }
        }
};
// Naive version — find() can degrade to O(n) if the tree becomes a long chain

2. The Naive Version's Problem — Long Chains

Without any optimization, repeated unions can build a long chain:

0 -> 1 -> 2 -> 3 -> 4 -> 5

find(0) now requires following 5 parent pointers — O(n) in the worst case,
which defeats the purpose of a fast connectivity structure. Two optimizations
fix this: PATH COMPRESSION and UNION BY RANK.

3. Optimization 1 — Path Compression

During find(), after locating the root, directly re-point every node visited along the way straight to that root — flattening the tree so future find() calls on those same nodes are nearly instant. 

int find(int x) {
    if (parent[x] == x) return x;
    return parent[x] = find(parent[x]);   // PATH COMPRESSION: re-point x directly to the root
                                              // as the recursion unwinds
}
// Every node on the path from x to the root gets flattened to point DIRECTLY at the root —
// so the NEXT find() call on any of those nodes is O(1)

Visualizing Path Compression

Before find(4), assuming chain: 0->1->2->3->4->5 (5 is the root)

find(0) traverses: 0->1->2->3->4->5, discovers root=5

AFTER path compression, EVERY node visited now points DIRECTLY to 5:
0->5, 1->5, 2->5, 3->5, 4->5

Any FUTURE find() on 0, 1, 2, 3, or 4 is now O(1) — a single pointer hop

4. Optimization 2 — Union by Rank (or Size)

When merging two sets, always attach the SMALLER (lower rank/size) tree under the root of the LARGER one — this prevents chains from growing unnecessarily long in the first place, complementing path compression. 

class DSU {
    public:
        vector<int> parent, rank_;

        DSU(int n) {
            parent.resize(n);
            rank_.assign(n, 0);
            for (int i = 0; i < n; i++) parent[i] = i;
        }

        int find(int x) {
            if (parent[x] == x) return x;
            return parent[x] = find(parent[x]);   // path compression
        }

        void unite(int x, int y) {
            int rootX = find(x);
            int rootY = find(y);
            if (rootX == rootY) return;   // already in the same set — nothing to do

            // UNION BY RANK — attach the smaller tree under the larger tree's root
            if (rank_[rootX] < rank_[rootY]) {
                parent[rootX] = rootY;
            } else if (rank_[rootX] > rank_[rootY]) {
                parent[rootY] = rootX;
            } else {
                parent[rootY] = rootX;   // equal rank — attach either way, then increment the new root's rank
                rank_[rootX]++;
            }
        }
};
// With BOTH optimizations combined, find() and unite() run in amortized O(α(n)) time —
// α is the INVERSE ACKERMANN function, which grows so slowly that it's effectively
// constant (≤ 5) for any input size that could ever exist in practice. This is
// considered "practically O(1)" for all real-world purposes.

5. Checking Connectivity

bool connected(DSU &dsu, int x, int y) {
    return dsu.find(x) == dsu.find(y);
}
// O(α(n)) — effectively O(1), thanks to both optimizations

6. Kruskal's Minimum Spanning Tree (MST) — the Classic DSU Application

Kruskal's algorithm builds a minimum spanning tree by greedily processing edges in increasing weight order, adding each edge UNLESS it would form a cycle — and DSU is exactly the right tool to check "would this edge create a cycle?" in near-constant time. 

struct Edge {
    int u, v, weight;
};

int kruskalMST(int n, vector<Edge> &edges) {
    sort(edges.begin(), edges.end(), [](Edge &a, Edge &b) {
        return a.weight < b.weight;   // process edges in ASCENDING weight order — greedy choice
    });

    DSU dsu(n);
    int totalWeight = 0;
    int edgesUsed = 0;

    for (Edge &e : edges) {
        if (dsu.find(e.u) != dsu.find(e.v)) {   // adding this edge would NOT create a cycle
            dsu.unite(e.u, e.v);
            totalWeight += e.weight;
            edgesUsed++;
            if (edgesUsed == n - 1) break;   // an MST always has exactly n-1 edges — done early
        }
        // else: this edge would connect two nodes ALREADY in the same set — SKIP it, it'd form a cycle
    }

    return totalWeight;
}
// O(E log E) time — dominated by sorting the edges; the DSU operations themselves
// are effectively O(1) each, contributing only O(E * α(n)) ≈ O(E) to the total

Why DSU is the perfect fit here: "would adding edge (u,v) create a cycle" is exactly equivalent to "are u and v already connected/in the same set" — a question DSU answers in near-constant time, which is why Kruskal's is efficient overall despite processing every edge.

7. Connected Components Using DSU (alternative to BFS/DFS from Module 6.8)

int countComponentsDSU(int n, vector<pair<int,int>> &edges) {
    DSU dsu(n);
    for (auto &[u, v] : edges) {
        dsu.unite(u, v);
    }

    unordered_set<int> uniqueRoots;
    for (int i = 0; i < n; i++) {
        uniqueRoots.insert(dsu.find(i));   // each distinct root represents one component
    }
    return uniqueRoots.size();
}
// O(n + E) effectively — an alternative to the BFS/DFS-based component counting
// from Module 6.8, particularly natural when edges arrive as a simple list
// rather than an adjacency structure
