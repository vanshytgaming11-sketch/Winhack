Module 6.3 — Linked Lists

While std::list (Module 4.1) provides a ready-made doubly linked list, interviews almost always ask you to implement and manipulate linked list logic manually — usually singly linked, using raw pointer-based nodes — to test your understanding of pointer manipulation directly.

1. Node Structure

struct ListNode {
    int val;
    ListNode *next;
    ListNode(int v) : val(v), next(nullptr) {}
};

// Building a small list manually: 1 -> 2 -> 3 -> nullptr
ListNode *head = new ListNode(1);
head->next = new ListNode(2);
head->next->next = new ListNode(3);
// head->next->next->next is implicitly nullptr — this is how a linked list "ends"

2. Singly vs Doubly Linked Lists

AspectSingly linkedDoubly linked
Pointers per nodeOne (next)Two (next and prev)
Traversal directionForward onlyBoth directions
Memory per nodeLessMore (extra pointer)
Deleting a given node directlyRequires the PREVIOUS node's pointer (must track it during traversal)Easy — the node itself has prev
 
struct DoublyListNode {
    int val;
    DoublyListNode *next;
    DoublyListNode *prev;
    DoublyListNode(int v) : val(v), next(nullptr), prev(nullptr) {}
};

3. Basic Traversal

void printList(ListNode *head) {
    ListNode *curr = head;
    while (curr != nullptr) {
        cout << curr->val << " -> ";
        curr = curr->next;
    }
    cout << "nullptr" << endl;
}
// O(n) time, O(1) space

4. Fast & Slow Pointers (Floyd's Technique)

The single most important linked-list-specific pattern: two pointers traverse the list at different speeds (typically slow moves 1 step, fast moves 2 steps per iteration). This solves problems that would otherwise require knowing the list's length in advance.

Finding the Middle Node

ListNode* findMiddle(ListNode *head) {
    ListNode *slow = head, *fast = head;
    while (fast != nullptr && fast->next != nullptr) {
        slow = slow->next;         // moves 1 step
        fast = fast->next->next;     // moves 2 steps
    }
    return slow;   // when fast reaches the end, slow is exactly at the middle
}
// O(n) time, O(1) space — no need to first count the list's length in a separate pass

Cycle Detection (Floyd's Cycle Detection / "Tortoise and Hare")

bool hasCycle(ListNode *head) {
    ListNode *slow = head, *fast = head;
    while (fast != nullptr && fast->next != nullptr) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) return true;   // they meet — a cycle exists
    }
    return false;   // fast reached nullptr — no cycle
}
// O(n) time, O(1) space — no extra memory needed (compare to a hash-set-of-visited-nodes approach, which is O(n) space)

Why they're guaranteed to meet if a cycle exists: once both pointers enter the cycle, fast gains on slow by exactly one node per iteration (since it moves 2 steps to slow's 1) — so it must eventually "lap" slow and land on the exact same node, within at most one full cycle length of iterations.

Finding the Start of the Cycle (extension)

ListNode* detectCycleStart(ListNode *head) {
    ListNode *slow = head, *fast = head;

    // Phase 1: detect if a cycle exists (as above)
    while (fast != nullptr && fast->next != nullptr) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) break;
    }

    if (fast == nullptr || fast->next == nullptr) return nullptr;   // no cycle

    // Phase 2: reset one pointer to head, then move BOTH one step at a time — they meet at the cycle's start
    slow = head;
    while (slow != fast) {
        slow = slow->next;
        fast = fast->next;
    }
    return slow;   // this is the node where the cycle begins
}
// This works due to the mathematical relationship between the distance to the cycle start
// and the cycle's length — a well-known but non-obvious proof, worth knowing exists even
// if you don't derive it from scratch in an interview.

5. Reversing a Linked List

One of the most frequently asked linked list problems — reverses the direction of every next pointer.

ListNode* reverseList(ListNode *head) {
    ListNode *prev = nullptr;
    ListNode *curr = head;

    while (curr != nullptr) {
        ListNode *nextTemp = curr->next;   // save the next node BEFORE overwriting curr->next
        curr->next = prev;                    // reverse the pointer
        prev = curr;                             // advance prev
        curr = nextTemp;                            // advance curr using the saved reference
    }
    return prev;   // prev is now the new head (was the last node before reversal)
}
// O(n) time, O(1) space — reverses in place, no new nodes allocated

Tracing Through It — 1→2→3→nullptr

Initial:   prev=null  curr=1  (1->2->3->null)

Step 1: nextTemp=2, 1->next=null, prev=1, curr=2
        State: null<-1   2->3->null

Step 2: nextTemp=3, 2->next=1, prev=2, curr=3
        State: null<-1<-2   3->null

Step 3: nextTemp=null, 3->next=2, prev=3, curr=null
        State: null<-1<-2<-3

Loop ends (curr==null). Return prev (=3) as the new head: 3->2->1->null

Recursive Reversal (alternative approach)

ListNode* reverseListRecursive(ListNode *head) {
    if (head == nullptr || head->next == nullptr) return head;   // base case — 0 or 1 node

    ListNode *newHead = reverseListRecursive(head->next);   // reverse everything AFTER head first

    head->next->next = head;   // make the node AFTER head point back to head
    head->next = nullptr;         // head becomes the new tail — must point to nullptr

    return newHead;   // the new head is established at the deepest base case, passed back up unchanged
}
// O(n) time, O(n) space (due to the recursive call stack) — worse space complexity than
// the iterative version, but often considered more elegant/easier to reason about

6. Common Node-Manipulation Operations

Inserting a node

void insertAtBeginning(ListNode *&head, int val) {   // note: reference to the pointer, to modify head itself
    ListNode *newNode = new ListNode(val);
    newNode->next = head;
    head = newNode;
}

void insertAfter(ListNode *node, int val) {
    ListNode *newNode = new ListNode(val);
    newNode->next = node->next;
    node->next = newNode;
}

Deleting a node (given the node itself, not the head)

void deleteNode(ListNode *prev, ListNode *toDelete) {
    prev->next = toDelete->next;
    delete toDelete;   // manually managing memory — this is why smart pointers (Module 5.3) are often used
                          // in production linked list implementations to avoid manual delete calls
}

7. Merging Two Sorted Lists

ListNode* mergeTwoLists(ListNode *l1, ListNode *l2) {
    ListNode dummy(0);           // a DUMMY node simplifies edge cases — avoids special-casing an empty result list
    ListNode *tail = &dummy;

    while (l1 != nullptr && l2 != nullptr) {
        if (l1->val <= l2->val) {
            tail->next = l1;
            l1 = l1->next;
        } else {
            tail->next = l2;
            l2 = l2->next;
        }
        tail = tail->next;
    }

    tail->next = (l1 != nullptr) ? l1 : l2;   // attach whichever list still has remaining nodes

    return dummy.next;   // dummy.next is the actual head of the merged list
}
// O(n + m) time, O(1) extra space (reuses existing nodes, no new allocation)

The dummy node trick: this is a widely used idiom for simplifying linked list code — instead of special-casing "what if the result list starts empty," you always start with a placeholder dummy node and return dummy.next at the end.

Practice Questions

Conceptual

  1. Explain why the fast/slow pointer technique correctly finds the middle of a list in a single pass, without knowing the list's length beforehand.
  2. Why are fast and slow pointers mathematically guaranteed to meet if a cycle exists?
  3. Explain, step by step, why nextTemp must be saved BEFORE reassigning curr->next in the iterative reversal function.
  4. Why does the recursive reversal have O(n) space complexity while the iterative version has O(1)?
  5. What problem does the "dummy node" idiom solve, and why does it simplify the merge-two-lists implementation?

Coding

  1. Write a function to detect a cycle in a linked list AND return its length if one exists (hint: once slow and fast meet, keep one pointer moving and count steps until it returns to the meeting point).
  2. Write a function that removes the Nth node from the end of a linked list in a SINGLE pass, using two pointers with a fixed gap.
  3. Write a function to check whether a linked list is a palindrome, using the fast/slow pointer technique to find the middle, then reversing the second half for comparison.
  4. Write a function to remove all duplicate values from an UNSORTED linked list, using a set to track values seen so far.
  5. Write a function to reorder a linked list L0→L1→...→Ln into L0→Ln→L1→Ln-1→... (find middle, reverse second half, merge alternately).
