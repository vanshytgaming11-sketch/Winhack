Module 6.4 — Stack & Queue Techniques

Module 4.3 covered stack, queue, and priority_queue as STL container adaptors. This module covers the specific algorithmic techniques built on top of them — most importantly the monotonic stack, plus common queue-based patterns using deque.

1. Monotonic Stack

A monotonic stack maintains its elements in strictly increasing or strictly decreasing order at all times — whenever a new element would violate that order, elements are popped off until the order is restored, then the new element is pushed. This pattern efficiently solves a whole family of "next greater/smaller element" problems in O(n) instead of the O(n²) brute force.

Next Greater Element

For each element, find the next element to its right that is strictly greater — or -1 if none exists.

vector<int> nextGreaterElement(vector<int> &arr) {
    int n = arr.size();
    vector<int> result(n, -1);
    stack<int> st;   // stores INDICES, maintained in DECREASING order of their VALUES

    for (int i = 0; i < n; i++) {
        // While current element is greater than the element at the index on top of the stack,
        // we've found that top element's "next greater" — pop it and record the answer
        while (!st.empty() && arr[i] > arr[st.top()]) {
            result[st.top()] = arr[i];
            st.pop();
        }
        st.push(i);
    }
    // Any indices remaining on the stack at the end have NO next greater element — result stays -1
    return result;
}
// O(n) time — even though there's a while loop inside a for loop, each index is pushed
// exactly once and popped AT MOST once across the entire run — same amortized reasoning as
// the sliding window's nested loop in Module 6.2.

// Example trace: arr = {2, 1, 2, 4, 3}
// result       = {4, 2, 4, -1, -1}

Why a Naive Approach Is O(n²)

// Brute force — for EACH element, scan RIGHT until a greater one is found
vector<int> nextGreaterBrute(vector<int> &arr) {
    int n = arr.size();
    vector<int> result(n, -1);
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            if (arr[j] > arr[i]) {
                result[i] = arr[j];
                break;
            }
        }
    }
    return result;
}
// O(n²) worst case — the monotonic stack approach above achieves the SAME result in O(n)
// by avoiding redundant re-scanning: each element is examined a constant number of times total.

Daily Temperatures (a very common variant)

// For each day, find how many days until a WARMER temperature — same monotonic stack pattern
vector<int> dailyTemperatures(vector<int> &temps) {
    int n = temps.size();
    vector<int> result(n, 0);
    stack<int> st;   // stores indices

    for (int i = 0; i < n; i++) {
        while (!st.empty() && temps[i] > temps[st.top()]) {
            int idx = st.top();
            st.pop();
            result[idx] = i - idx;   // DISTANCE (in days), not the value itself
        }
        st.push(i);
    }
    return result;
}
// O(n) time — same monotonic stack pattern, just tracking distance instead of the value

Largest Rectangle in Histogram (classic advanced monotonic stack problem)

int largestRectangleArea(vector<int> &heights) {
    stack<int> st;   // maintains indices of bars in INCREASING height order
    int maxArea = 0;
    heights.push_back(0);   // sentinel — forces the stack to fully empty by the end, simplifying the code

    for (int i = 0; i < heights.size(); i++) {
        while (!st.empty() && heights[i] < heights[st.top()]) {
            int height = heights[st.top()];
            st.pop();
            int width = st.empty() ? i : i - st.top() - 1;
            maxArea = max(maxArea, height * width);
        }
        st.push(i);
    }
    return maxArea;
}
// O(n) time — a more advanced application of the same monotonic stack idea

2. Monotonic Stack — Recognizing When to Use It

The monotonic stack pattern applies whenever a problem asks, for each element, about the nearest element satisfying some comparison (greater, smaller, or a derived property like "nearest bar tall enough") to its left or right — this is the signal to reach for it instead of brute-force nested loops.

3. Monotonic Queue (Sliding Window Maximum)

A monotonic deque solves the "maximum in every sliding window of size K" problem in O(n), by maintaining indices in decreasing order of their values, and discarding indices that fall outside the current window or that can never be the maximum again. 

vector<int> maxSlidingWindow(vector<int> &arr, int k) {
    deque<int> dq;   // stores INDICES, values at those indices are kept in DECREASING order
    vector<int> result;

    for (int i = 0; i < arr.size(); i++) {
        // Remove indices that have fallen out of the current window (out the LEFT side)
        if (!dq.empty() && dq.front() <= i - k) {
            dq.pop_front();
        }

        // Remove indices from the BACK whose values are smaller than the current element —
        // they can NEVER be the max while arr[i] is still in the window, so they're useless
        while (!dq.empty() && arr[dq.back()] < arr[i]) {
            dq.pop_back();
        }

        dq.push_back(i);

        if (i >= k - 1) {           // window has reached full size — record the current max
            result.push_back(arr[dq.front()]);   // front always holds the max for the current window
        }
    }
    return result;
}
// O(n) time — each index is pushed once and popped at most once, same amortized reasoning as before
// Compare to the brute-force approach of recomputing the max for every window: O(n*k)

Practice Questions

Conceptual

  1. Explain why the "next greater element" solution using a monotonic stack is O(n), even though it contains a nested while loop.
  2. What signal in a problem statement suggests a monotonic stack is the right approach, as opposed to a plain stack or a different technique?
  3. In the sliding window maximum problem, explain why elements smaller than the current one can be safely discarded from the back of the deque.
  4. Why is the front of the monotonic deque always the maximum of the current window, without needing to scan the whole window?

Coding

  1. Write a function using a monotonic stack to find the "next smaller element" for each element in an array (mirror image of "next greater element").
  2. Write a function to find, for each element in an array, the index of the previous greater element to its LEFT (a common variant direction).
  3. Implement the sliding window minimum (mirror of sliding window maximum) using a monotonic deque.
  4. Write a function using a monotonic stack to solve the "Trapping Rain Water" problem — given an array of bar heights, compute how much water is trapped between them.
