Module 6.10 — Dynamic Programming

Dynamic Programming (DP) solves problems by breaking them into overlapping subproblems, solving each subproblem only ONCE, and reusing (rather than recomputing) those results. Module 1.3 previewed this exact motivation with the exponential naive Fibonacci — this module formalizes DP as a general technique, covering both its two core implementation styles and its most common patterns.

1. The Core DP Requirement — Overlapping Subproblems + Optimal Substructure

A problem is a DP candidate when it has: overlapping subproblems (the same smaller subproblem is needed multiple times during a naive recursive solution), and optimal substructure (the optimal solution to the whole problem can be constructed from optimal solutions to its subproblems).

2. Memoization (Top-Down)

Starts from the recursive solution and adds a cache: before computing a subproblem, check if it's already been solved; if so, return the cached result instead of recomputing. 

// Naive recursive Fibonacci — O(2^n), from Module 1.3
int fibNaive(int n) {
    if (n <= 1) return n;
    return fibNaive(n-1) + fibNaive(n-2);
}

// MEMOIZED version — O(n) time, O(n) space (cache + recursion stack)
unordered_map<int, int> memo;

int fibMemo(int n) {
    if (n <= 1) return n;
    if (memo.count(n)) return memo[n];   // ALREADY SOLVED — return cached result immediately

    memo[n] = fibMemo(n-1) + fibMemo(n-2);   // solve, then CACHE before returning
    return memo[n];
}
// A vector<int> cache initialized to -1 (as a "not yet computed" sentinel) is often
// used instead of unordered_map when the subproblem space is a small, dense range of integers —
// slightly faster due to O(1) guaranteed array access vs hash map overhead

Why Memoization Fixes the Exponential Blowup

Naive recursion tree for fib(5) — note fib(3) computed TWICE, fib(2) THREE times:
                    fib(5)
                 /          \
             fib(4)          fib(3)
            /      \        /      \
        fib(3)   fib(2)  fib(2)   fib(1)
        /    \    /   \   /   \
    fib(2) fib(1) ...  ...  ...

With memoization, each fib(k) is computed EXACTLY ONCE, then reused instantly
on every subsequent request — turning O(2^n) into O(n).

3. Tabulation (Bottom-Up)

Builds the solution iteratively from the smallest subproblems upward, filling a table (usually an array), without any recursion or call-stack overhead. 

int fibTabulation(int n) {
    if (n <= 1) return n;

    vector<int> dp(n + 1);
    dp[0] = 0;
    dp[1] = 1;

    for (int i = 2; i <= n; i++) {
        dp[i] = dp[i-1] + dp[i-2];   // build UP from already-solved smaller subproblems
    }

    return dp[n];
}
// O(n) time, O(n) space — same complexity as memoization, but NO recursive call stack overhead

Space-Optimized Tabulation

Many DP problems only need the last 1-2 previous states, not the entire table — this observation often reduces O(n) space to O(1):

int fibOptimized(int n) {
    if (n <= 1) return n;

    int prev2 = 0, prev1 = 1;
    for (int i = 2; i <= n; i++) {
        int curr = prev1 + prev2;
        prev2 = prev1;
        prev1 = curr;
    }
    return prev1;
}
// O(n) time, O(1) space — the full table was never actually needed, only the last two values

5. Common DP Pattern — 0/1 Knapsack

Given items with weights and values, and a weight capacity, maximize total value without exceeding capacity — each item can be used at most once (hence "0/1": include or exclude).

int knapsack(vector<int> &weights, vector<int> &values, int capacity) {
    int n = weights.size();
    vector<vector<int>> dp(n + 1, vector<int>(capacity + 1, 0));
    // dp[i][w] = max value achievable using the FIRST i items, with capacity w

    for (int i = 1; i <= n; i++) {
        for (int w = 0; w <= capacity; w++) {
            dp[i][w] = dp[i-1][w];   // OPTION 1: don't include item i-1

            if (weights[i-1] <= w) {   // OPTION 2: include item i-1, if it fits
                dp[i][w] = max(dp[i][w], dp[i-1][w - weights[i-1]] + values[i-1]);
            }
        }
    }
    return dp[n][capacity];
}
// O(n * capacity) time and space — this is PSEUDO-polynomial: efficient for reasonable
// capacity values, but can become slow if capacity is astronomically large,
// since the complexity depends on capacity's VALUE, not just the number of items

6. Common DP Pattern — Longest Increasing Subsequence (LIS)

int lengthOfLIS(vector<int> &nums) {
    int n = nums.size();
    vector<int> dp(n, 1);   // dp[i] = length of the longest increasing subsequence ENDING at index i

    for (int i = 1; i <= n - 1; i++) {
        for (int j = 0; j < i; j++) {
            if (nums[j] < nums[i]) {
                dp[i] = max(dp[i], dp[j] + 1);
            }
        }
    }

    return *max_element(dp.begin(), dp.end());
}
// O(n²) time — the classic DP approach. An O(n log n) approach exists using
// binary search (patience sorting technique), but the O(n²) DP version is
// the standard interview baseline and demonstrates the pattern most clearly.

7. Common DP Pattern — Longest Common Subsequence (LCS)

int longestCommonSubsequence(string text1, string text2) {
    int m = text1.length(), n = text2.length();
    vector<vector<int>> dp(m + 1, vector<int>(n + 1, 0));
    // dp[i][j] = LCS length using the first i chars of text1 and first j chars of text2

    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (text1[i-1] == text2[j-1]) {
                dp[i][j] = dp[i-1][j-1] + 1;   // characters match — extend the previous diagonal LCS
            } else {
                dp[i][j] = max(dp[i-1][j], dp[i][j-1]);   // no match — take the best of excluding either character
            }
        }
    }
    return dp[m][n];
}
// O(m*n) time and space — a classic 2D DP pattern, foundational for edit distance and
// diff-tool-style algorithms

8. Common DP Pattern — Partition Problems

// Determine if an array can be partitioned into two subsets with EQUAL sum
bool canPartition(vector<int> &nums) {
    int sum = accumulate(nums.begin(), nums.end(), 0);   // Module 4.7
    if (sum % 2 != 0) return false;   // odd total sum can NEVER split into two equal halves

    int target = sum / 2;
    vector<bool> dp(target + 1, false);
    dp[0] = true;   // a sum of 0 is always achievable (the empty subset)

    for (int num : nums) {
        for (int w = target; w >= num; w--) {   // iterate BACKWARD — prevents reusing the same item twice
            dp[w] = dp[w] || dp[w - num];
        }
    }
    return dp[target];
}
// This is a DISGUISED 0/1 Knapsack: "can we hit exactly this target sum using each
// item at most once" — recognizing this connection to Knapsack is a key interview insight.
// O(n * target) time — iterating BACKWARD in the inner loop is what enforces the "each item once" rule,
// a subtle but critical detail: iterating forward would allow reusing the same item multiple times

9. Recognizing DP Problems — Signal Checklist

  • The problem asks for a maximum, minimum, count, or yes/no feasibility, involving a sequence of choices.
  • A brute-force recursive solution would revisit the same subproblem multiple times (overlapping subproblems).
  • The problem can be broken into "the answer for a smaller version of the same problem, plus a small amount of extra work."
  • Keywords: "maximum/minimum", "number of ways", "can you achieve", "longest/shortest subsequence/substring."

Practice Questions

Conceptual

  1. Explain overlapping subproblems and optimal substructure — why does a problem need BOTH properties to be a good DP candidate?
  2. Compare memoization and tabulation — in what scenario would memoization be preferable despite its extra call-stack overhead?
  3. Explain why the 0/1 Knapsack's complexity, O(n * capacity), is called "pseudo-polynomial" rather than truly polynomial.
  4. In the "equal sum partition" problem, explain why the inner loop must iterate backward through capacities, and what would go wrong if it iterated forward instead.
  5. Explain how "equal sum partition" is a disguised version of 0/1 Knapsack — what maps to what?

Coding

  1. Write both a memoized (top-down) and tabulated (bottom-up) solution for the "climbing stairs" problem (count ways to reach step n, taking 1 or 2 steps at a time).
  2. Write a DP solution for the "coin change" problem: given coin denominations and a target amount, find the minimum number of coins needed (or -1 if impossible).
  3. Write a DP solution for "edit distance": given two strings, find the minimum number of insertions/deletions/substitutions to convert one into the other (extends the LCS pattern above).
  4. Write a DP solution for the "house robber" problem: given an array of house values, find the maximum sum obtainable without robbing two adjacent houses.
  5. Write a space-optimized (O(1) extra space beyond the input) DP solution for the "maximum subarray sum" problem (Kadane's algorithm).
