Module 6.6 — Trees

A tree is a hierarchical, non-linear data structure consisting of nodes connected by edges, with exactly one root and no cycles. Binary trees — where each node has at most two children — are by far the most heavily tested tree structure in interviews, and recursion (Module 1.3) is almost always the natural way to process them.

1. Binary Tree — Node Structure

struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode(int v) : val(v), left(nullptr), right(nullptr) {}
};

//         1
//        / \
//       2   3
//      / \
//     4   5
TreeNode *root = new TreeNode(1);
root->left = new TreeNode(2);
root->right = new TreeNode(3);
root->left->left = new TreeNode(4);
root->left->right = new TreeNode(5);

2. Tree Terminology

TermMeaning
RootThe topmost node — has no parent
LeafA node with no children
HeightLongest path from a node down to a leaf (number of edges)
DepthDistance from the root to a given node (number of edges)
SubtreeA node together with all of its descendants
BalancedThe height difference between any node's left and right subtrees is at most 1
CompleteEvery level is fully filled except possibly the last, which fills left to right

3. Tree Traversals — Depth-First (DFS)

Three DFS orderings differ only in WHEN the current node is visited relative to its children — all are O(n) time, O(h) space (h = tree height, due to the recursive call stack).

Inorder (Left → Node → Right)

void inorder(TreeNode *root) {
    if (root == nullptr) return;
    inorder(root->left);
    cout << root->val << " ";
    inorder(root->right);
}
// For the tree above: 4 2 5 1 3
// CRITICAL property: inorder traversal of a BST always produces SORTED order (Module 6.6 section 6)

Preorder (Node → Left → Right)

void preorder(TreeNode *root) {
    if (root == nullptr) return;
    cout << root->val << " ";
    preorder(root->left);
    preorder(root->right);
}
// Output: 1 2 4 5 3
// Common use: serializing a tree's structure (the root always comes before its children)

Postorder (Left → Right → Node)

void postorder(TreeNode *root) {
    if (root == nullptr) return;
    postorder(root->left);
    postorder(root->right);
    cout << root->val << " ";
}
// Output: 4 5 2 3 1
// Common use: deleting a tree safely (children must be freed BEFORE their parent),
// or evaluating an expression tree (operands before the operator)

Iterative DFS (using an explicit stack — avoiding recursion)

void preorderIterative(TreeNode *root) {
    if (root == nullptr) return;
    stack<TreeNode*> st;
    st.push(root);

    while (!st.empty()) {
        TreeNode *curr = st.top();
        st.pop();
        cout << curr->val << " ";

        // Push RIGHT first so LEFT is processed first (stack is LIFO)
        if (curr->right) st.push(curr->right);
        if (curr->left) st.push(curr->left);
    }
}
// This directly mirrors what the recursive call stack does implicitly —
// exactly connecting back to Module 1.3's discussion of recursion vs iteration

4. Tree Traversal — Breadth-First (BFS / Level-Order)

Visits nodes level by level, using a queue (Module 4.3) rather than a stack — this is the tree-specific application of the queue-based BFS previewed in Module 6.4.

void levelOrder(TreeNode *root) {
    if (root == nullptr) return;
    queue<TreeNode*> q;
    q.push(root);

    while (!q.empty()) {
        TreeNode *curr = q.front();
        q.pop();
        cout << curr->val << " ";

        if (curr->left) q.push(curr->left);
        if (curr->right) q.push(curr->right);
    }
}
// Output: 1 2 3 4 5
// O(n) time, O(w) space, where w = the tree's maximum width (widest level)

Level-Order with Level Separation (common variant)

vector<vector<int>> levelOrderGrouped(TreeNode *root) {
    vector<vector<int>> result;
    if (root == nullptr) return result;
    queue<TreeNode*> q;
    q.push(root);

    while (!q.empty()) {
        int levelSize = q.size();   // snapshot the CURRENT level's size before processing
        vector<int> level;

        for (int i = 0; i < levelSize; i++) {
            TreeNode *curr = q.front();
            q.pop();
            level.push_back(curr->val);

            if (curr->left) q.push(curr->left);
            if (curr->right) q.push(curr->right);
        }
        result.push_back(level);
    }
    return result;
}
// Output for the example tree: {{1}, {2,3}, {4,5}}
// The trick: capture q.size() BEFORE the inner loop, since new children get pushed
// DURING the loop and would otherwise incorrectly be counted as part of the current level

5. Recursion Patterns on Trees

Most tree problems follow one of a few recursive templates — recognizing which applies is often the key interview insight.

Pattern A — Compute a value bottom-up from children

int height(TreeNode *root) {
    if (root == nullptr) return -1;   // convention: height of an empty tree is -1 (or 0, depending on definition)
    return 1 + max(height(root->left), height(root->right));
}
// O(n) time — visits every node exactly once
// O(h) space — recursive call stack depth equals the tree's height
int countNodes(TreeNode *root) {
    if (root == nullptr) return 0;
    return 1 + countNodes(root->left) + countNodes(root->right);
}

Pattern B — Check a property recursively, combining results from children

bool isBalanced(TreeNode *root) {
    return checkHeight(root) != -1;   // helper returns -1 as a sentinel meaning "already unbalanced"
}

int checkHeight(TreeNode *root) {
    if (root == nullptr) return 0;

    int leftHeight = checkHeight(root->left);
    if (leftHeight == -1) return -1;   // propagate the "unbalanced" signal up immediately

    int rightHeight = checkHeight(root->right);
    if (rightHeight == -1) return -1;

    if (abs(leftHeight - rightHeight) > 1) return -1;   // THIS node violates balance

    return 1 + max(leftHeight, rightHeight);
}
// O(n) time — this combined approach avoids the O(n²) naive version that would
// recompute height() separately at every single node

Pattern C — Path-based problems (passing state DOWN through parameters)

bool hasPathSum(TreeNode *root, int targetSum) {
    if (root == nullptr) return false;

    if (root->left == nullptr && root->right == nullptr) {   // leaf node
        return targetSum == root->val;
    }

    int remaining = targetSum - root->val;
    return hasPathSum(root->left, remaining) || hasPathSum(root->right, remaining);
}
// The "remaining target" is passed DOWN the recursion — a common technique for
// path-sum-style problems, distinct from Pattern A's bottom-up value computation

6. Binary Search Trees (BST)

A BST is a binary tree with an ordering invariant: for every node, all values in its LEFT subtree are smaller, and all values in its RIGHT subtree are larger. This invariant is exactly what makes inorder traversal produce sorted output (as noted in section 3), and what enables O(h) search/insert/delete.

BST Search

TreeNode* searchBST(TreeNode *root, int target) {
    if (root == nullptr || root->val == target) return root;
    if (target < root->val) return searchBST(root->left, target);
    return searchBST(root->right, target);
}
// O(h) time — where h is the tree's height. For a BALANCED BST, h = O(log n).
// For a DEGENERATE (essentially linked-list-shaped) BST, h = O(n) — same worst case as Module 4.8's
// discussion of unbalanced BSTs, which is exactly why std::map uses a SELF-BALANCING tree internally.

BST Insertion

TreeNode* insertBST(TreeNode *root, int val) {
    if (root == nullptr) return new TreeNode(val);

    if (val < root->val) {
        root->left = insertBST(root->left, val);
    } else {
        root->right = insertBST(root->right, val);
    }
    return root;
}
// O(h) time — traverses down to find the correct empty spot, following the BST invariant at each step

Validating a BST (common interview trap)

bool isValidBST(TreeNode *root, long minVal = LONG_MIN, long maxVal = LONG_MAX) {
    if (root == nullptr) return true;

    if (root->val <= minVal || root->val >= maxVal) return false;

    return isValidBST(root->left, minVal, root->val) &&
           isValidBST(root->right, root->val, maxVal);
}
// COMMON BUG: checking only `root->left->val < root->val < root->right->val` at EACH node
// individually is WRONG — it misses violations further down the tree. The valid range must be
// PASSED DOWN and narrowed at every level, since a BST's invariant applies to the ENTIRE subtree,
// not just immediate children.

Practice Questions

Conceptual

  1. Explain why inorder traversal of a BST always produces values in sorted order, referencing the BST invariant.
  2. Why does level-order traversal require capturing q.size() before the inner loop when grouping nodes by level?
  3. Explain the bug in checking only immediate children's values when validating a BST, and why the min/max range must be passed down recursively.
  4. What is the time complexity of BST search/insert in the best case (balanced) versus worst case (degenerate)? Why does this connect back to Module 4.8's discussion of set/map?
  5. Explain the difference between the three DFS orderings (preorder, inorder, postorder) and give a practical use case for each.

Coding

  1. Write a function to find the lowest common ancestor (LCA) of two nodes in a BST, using the BST property to avoid a full traversal.
  2. Write a function to serialize a binary tree to a string (preorder with null markers) and deserialize it back into a tree.
  3. Write a function to check if two binary trees are structurally identical (same shape and same values at every node).
  4. Write a function to find the diameter of a binary tree (the longest path between any two nodes, not necessarily through the root) in O(n), combining Pattern A and Pattern B above.
  5. Write a function to convert a sorted array into a height-balanced BST.
  6. Write a function to find the K-th smallest element in a BST using inorder traversal, stopping early once the K-th element is reached.
