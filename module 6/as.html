Module 6.2 — Arrays & Strings (Patterns)

Module 1.4 covered array/string mechanics. This module covers the recurring algorithmic patterns used to solve array/string interview problems efficiently: traversal variants, prefix sums, two pointers, and sliding window. These four patterns alone solve a large fraction of all array/string interview questions.

1. Traversal Variants

Beyond simple left-to-right traversal, several traversal patterns come up repeatedly:

Traversing from both ends simultaneously

// Used heavily in two-pointer problems (section 3 below)
int left = 0, right = arr.size() - 1;
while (left < right) {
    // process arr[left] and arr[right]
    left++;
    right--;
}

Traversing with a "look-ahead" or "look-behind"

// Compare each element to the next
for (int i = 0; i < arr.size() - 1; i++) {
    if (arr[i] > arr[i+1]) {
        cout << "Not sorted at index " << i;
    }
}

2. Prefix Sums

A prefix sum array precomputes cumulative sums, so that the sum of ANY subarray [l, r] can be answered in O(1) after O(n) preprocessing — instead of O(n) per query with a naive approach. 

vector<int> arr = {3, 1, 4, 1, 5, 9, 2};

// Build prefix sum: prefix[i] = sum of arr[0..i-1]
vector<int> prefix(arr.size() + 1, 0);
for (int i = 0; i < arr.size(); i++) {
    prefix[i + 1] = prefix[i] + arr[i];
}
// prefix = {0, 3, 4, 8, 9, 14, 23, 25}

// Sum of subarray [l, r] INCLUSIVE = prefix[r+1] - prefix[l]
int sumRange = prefix[5] - prefix[2];   // sum of arr[2..4] = 4+1+5 = 10
cout << sumRange;                          // 10

Why this matters: if you need to answer MANY range-sum queries on the same array, prefix sums turn an O(n) per-query brute force into O(1) per query, after a one-time O(n) setup — a massive improvement when there are many queries.

2D Prefix Sums (brief extension)

// For a matrix, prefix2D[i][j] = sum of all elements in the rectangle from (0,0) to (i-1,j-1)
// Allows O(1) sum queries over any rectangular sub-region after O(rows*cols) preprocessing —
// the 2D generalization of the same idea, common in matrix-heavy interview problems.

3. Two-Pointer Technique

Uses two indices that move through the array according to some logic — either from opposite ends converging inward, or both moving forward at different speeds. This typically reduces an O(n²) brute force to O(n).

Pattern A — Opposite Ends Converging (already previewed in Module 1.4)

bool isPalindrome(string s) {
    int left = 0, right = s.length() - 1;
    while (left < right) {
        if (s[left] != s[right]) return false;
        left++;
        right--;
    }
    return true;
}
// O(n) time, O(1) space

Two Sum on a SORTED Array (classic two-pointer application)

pair<int,int> twoSumSorted(vector<int> &arr, int target) {
    int left = 0, right = arr.size() - 1;
    while (left < right) {
        int sum = arr[left] + arr[right];
        if (sum == target) return {left, right};
        else if (sum < target) left++;    // sum too small — need a bigger value, move left pointer up
        else right--;                          // sum too large — need a smaller value, move right pointer down
    }
    return {-1, -1};   // not found
}
// O(n) time — compare to the brute-force O(n²) nested-loop approach

Why this works: because the array is sorted, moving left forward strictly increases the sum, and moving right backward strictly decreases it — this monotonic property is exactly what lets two pointers replace a nested loop.

Pattern B — Fast/Slow Pointers (same direction, different speeds)

This variant is covered in full depth in Module 6.3 (Linked Lists), where it's most commonly applied — but it works on arrays too:

// Remove duplicates from a SORTED array in place, return new length
int removeDuplicates(vector<int> &arr) {
    if (arr.empty()) return 0;
    int slow = 0;   // tracks the position of the last unique element
    for (int fast = 1; fast < arr.size(); fast++) {
        if (arr[fast] != arr[slow]) {
            slow++;
            arr[slow] = arr[fast];
        }
    }
    return slow + 1;   // new logical length
}
// O(n) time, O(1) EXTRA space (modifies in place)

4. Sliding Window

Maintains a "window" (a contiguous subrange) that expands and/or contracts as it moves across the array/string, avoiding redundant recomputation. Used for subarray/substring problems involving a size constraint, a sum constraint, or a uniqueness constraint.

Fixed-Size Window — Maximum Sum Subarray of Size K

int maxSumSubarray(vector<int> &arr, int k) {
    int windowSum = 0;
    for (int i = 0; i < k; i++) windowSum += arr[i];   // sum of the FIRST window

    int maxSum = windowSum;
    for (int i = k; i < arr.size(); i++) {
        windowSum += arr[i] - arr[i - k];   // SLIDE: add new element, remove the one leaving the window
        maxSum = max(maxSum, windowSum);
    }
    return maxSum;
}
// O(n) time — compare to brute force recomputing each window's sum from scratch, which would be O(n*k)

Variable-Size Window — Smallest Subarray with Sum ≥ Target

int minSubarrayLen(vector<int> &arr, int target) {
    int left = 0, sum = 0, minLen = INT_MAX;

    for (int right = 0; right < arr.size(); right++) {
        sum += arr[right];                        // EXPAND the window by including arr[right]

        while (sum >= target) {                      // window is big enough — try to SHRINK it
            minLen = min(minLen, right - left + 1);
            sum -= arr[left];
            left++;
        }
    }
    return (minLen == INT_MAX) ? 0 : minLen;
}
// O(n) time — even though there's a nested while loop, each element is added and removed
// from the window AT MOST ONCE across the entire run, so the total work is still O(n), not O(n²)

Why this is still O(n), despite the nested loop: the right pointer advances exactly n times total, and the left pointer also advances at most n times total (across the ENTIRE function run, not per outer iteration) — so total work across both loops combined is O(n) + O(n) = O(n), not O(n²). This is a subtle but frequently-tested complexity analysis point.

Variable-Size Window — Longest Substring Without Repeating Characters

int lengthOfLongestSubstring(string s) {
    unordered_set<char> window;
    int left = 0, maxLen = 0;

    for (int right = 0; right < s.length(); right++) {
        while (window.count(s[right])) {         // duplicate found — shrink from the left until it's gone
            window.erase(s[left]);
            left++;
        }
        window.insert(s[right]);
        maxLen = max(maxLen, right - left + 1);
    }
    return maxLen;
}
// O(n) time (amortized, same reasoning as above), O(min(n, charset size)) space

5. Choosing the Right Pattern — Quick Reference

Signal in the problemLikely pattern
"Sum of a range" queried multiple timesPrefix sums
Sorted array, looking for a pair/triplet matching a conditionTwo pointers (converging)
"Remove duplicates in place", "partition array"Two pointers (fast/slow, same direction)
"Subarray of size K", "max/min sum of a fixed-size window"Sliding window (fixed size)
"Smallest/longest subarray satisfying a condition"Sliding window (variable size)

Practice Questions

Conceptual

  1. Explain why the variable-size sliding window approach for "smallest subarray with sum ≥ target" is O(n) despite containing a nested loop.
  2. Why does the two-pointer approach for two-sum require the array to be SORTED first? What would go wrong on unsorted data?
  3. Explain how prefix sums turn an O(n) per-query range-sum operation into O(1), and what the one-time setup cost is.
  4. What's the key difference between the "converging" and "fast/slow" two-pointer patterns — when would you use each?

Coding

  1. Write a function using prefix sums to answer multiple range-sum queries efficiently on a static array, given as a list of (l, r) pairs.
  2. Write a two-pointer function that finds all unique triplets in an array that sum to zero (the classic "3Sum" problem) — sort first, then fix one element and two-pointer the rest.
  3. Write a sliding window function that finds the length of the longest subarray containing at most K distinct integers.
  4. Write a function using the fast/slow two-pointer pattern to move all zeros in an array to the end, while maintaining the relative order of non-zero elements, in place.
  5. Write a sliding window function to find all starting indices of anagrams of a pattern string p within a string s (fixed-size window, using frequency maps).
