Module 6.5 — Hashing

Module 4.5 covered unordered_map/unordered_set as STL tools. This module covers hashing as an algorithmic technique — how hash functions work conceptually, collision handling strategies, and the recurring interview pattern of using frequency maps to convert brute-force O(n²) solutions into O(n).

1. How Hash Functions Work (Conceptual)

A hash function takes a key of (potentially) any size and type and deterministically maps it to a fixed-size integer (the hash code), which is then reduced (usually via modulo) to an index within the hash table's array of buckets. 

// Conceptual pseudocode — NOT how std::hash is actually implemented internally, but illustrates the idea:
int simpleHash(string key, int tableSize) {
    int hash = 0;
    for (char c : key) {
        hash = (hash * 31 + c) % tableSize;   // a common technique — multiply by a prime, add char value
    }
    return hash;
}

Properties of a good hash function:

  • Deterministic — the same key always produces the same hash.
  • Uniform distribution — spreads keys evenly across buckets, minimizing collisions.
  • Fast to compute — hashing itself shouldn't become the bottleneck.

2. Collision Handling

A collision occurs when two different keys hash to the same bucket. No hash function can be perfectly collision-free for arbitrary input (by the pigeonhole principle — there are more possible keys than buckets), so every hash table implementation needs a collision-handling strategy.

Strategy 1 — Separate Chaining (what unordered_map typically uses)

Each bucket holds a small linked list (or similar structure) of all elements that hashed to it. On a collision, the new element is simply appended to that bucket's list.

Bucket 0: []
Bucket 1: [("apple", 5)] -> [("grape", 12)]   ← both hashed to bucket 1, chained together
Bucket 2: [("banana", 3)]
Bucket 3: []

Lookup requires hashing the key to find the right bucket, then linearly scanning that bucket's (usually short) chain — O(1) average when chains stay short, degrading toward O(n) if too many keys collide into the same bucket (the worst-case scenario referenced in Module 4.5).

Strategy 2 — Open Addressing (an alternative, used by some other languages/implementations)

On a collision, the table probes for the next available slot (e.g., linearly checking the next index, or using a secondary hash) instead of chaining. Not used by the standard unordered_map implementation, but worth knowing conceptually for interviews that ask about hash table design.

3. Load Factor and Rehashing (recap, tied to Module 4.5)

unordered_map<string, int> m;
cout << m.load_factor();    // elements / bucket_count — the average chain length
// As elements are inserted and load_factor crosses a threshold (typically ~1.0),
// the table automatically REHASHES: allocates more buckets and redistributes every
// existing element — an O(n) operation, but amortized across many insertions it doesn't
// change the overall O(1) average complexity, similar to vector's amortized O(1) push_back.

4. Frequency Maps — The Core Interview Pattern

The single most common hashing application in interviews: building a map (or array, for small fixed alphabets) that counts occurrences of each distinct value, then using that map to answer a question in O(n) that would otherwise require O(n²) comparisons.

Two Sum (unsorted array — the classic hashing example)

vector<int> twoSum(vector<int> &arr, int target) {
    unordered_map<int, int> seen;   // value -> index

    for (int i = 0; i < arr.size(); i++) {
        int complement = target - arr[i];
        if (seen.count(complement)) {
            return {seen[complement], i};   // found a matching pair
        }
        seen[arr[i]] = i;   // record this value's index for future lookups
    }
    return {};   // no solution found
}
// O(n) time, O(n) space — a SINGLE pass, compare to the O(n²) brute-force nested loop

This is a direct improvement over the sorted-array two-pointer version from Module 6.2: on unsorted data, sorting first would cost O(n log n) — using a hash map instead achieves O(n), a genuine improvement, at the cost of O(n) extra space.

Anagram Grouping

vector<vector<string>> groupAnagrams(vector<string> &strs) {
    unordered_map<string, vector<string>> groups;

    for (string &s : strs) {
        string key = s;
        sort(key.begin(), key.end());   // anagrams share the SAME sorted form — this becomes the map key
        groups[key].push_back(s);
    }

    vector<vector<string>> result;
    for (auto &entry : groups) {
        result.push_back(entry.second);
    }
    return result;
}
// O(n * k log k) time, where n = number of strings, k = average string length (dominated by sorting each string)

Subarray Sum Equals K (prefix sum + hash map combined — a powerful combo)

int subarraySum(vector<int> &arr, int k) {
    unordered_map<int, int> prefixCount;
    prefixCount[0] = 1;   // an empty prefix (sum 0) has occurred once — handles subarrays starting at index 0

    int sum = 0, count = 0;
    for (int x : arr) {
        sum += x;
        // If (sum - k) has been seen before as a prefix sum, then the subarray
        // BETWEEN that earlier point and now sums to exactly k
        if (prefixCount.count(sum - k)) {
            count += prefixCount[sum - k];
        }
        prefixCount[sum]++;
    }
    return count;
}
// O(n) time, O(n) space — combines the prefix sum idea from Module 6.2 with a hash map
// to avoid the O(n²) brute force of checking every possible subarray

Practice Questions

Conceptual

  1. Explain separate chaining as a collision-handling strategy, and why it degrades toward O(n) lookups when too many keys land in the same bucket.
  2. Why is a hash-map-based two-sum solution generally preferred over sorting the array first and using two pointers?
  3. Explain why prefixCount[0] = 1 is necessary in the subarray-sum-equals-K solution — what case would be missed without it?
  4. Why does sorting each string to use as a map key correctly group all anagrams together?

Coding

  1. Write a function that finds the first non-repeating character in a string using a frequency map, in O(n) time.
  2. Write a function that checks whether two arrays are equal ignoring order (i.e., they contain the same elements with the same frequencies) using a hash map.
  3. Write a function that finds the longest consecutive sequence of integers in an unsorted array (e.g., {100, 4, 200, 1, 3, 2} → 4, for the sequence 1,2,3,4) in O(n) using a hash set.
  4. Write a function that counts the number of pairs in an array whose difference equals a given K, using a hash map.
  5. Write a function that determines if a Sudoku board's current state is valid (no repeated digits in any row, column, or 3x3 box) using hash sets.
