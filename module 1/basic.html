Module 1.1 — C++ Basics

1. Introduction to C++

C++ is a general-purpose, compiled, statically-typed programming language created by Bjarne Stroustrup in 1979 at Bell Labs, initially as an extension of the C language (originally called "C with Classes"). It was designed to add object-oriented capabilities to C while retaining C's performance and low-level control over memory and hardware.

Why C++ matters for interviews and real-world systems:

PropertyWhat it means
Compiled languageSource code is translated directly into machine code before execution → very fast runtime performance
Statically typedVariable types are checked at compile time, not runtime → catches errors early
Multi-paradigmSupports procedural, object-oriented, and generic programming in one language
Manual memory controlYou control allocation/deallocation directly → power, but also responsibility
Rich standard libraryThe STL (Standard Template Library) provides ready-made, highly optimized data structures and algorithms

C++ is used in system software (OS kernels, browsers), game engines, high-frequency trading systems, embedded systems, and is one of the most commonly asked languages in DSA/competitive programming interviews because it gives you both control and a powerful standard library.

2. Compilation & Execution

Unlike interpreted languages (Python, JavaScript), C++ code must be compiled into machine code before it runs. Understanding this pipeline is a common interview question in itself.

The Compilation Pipeline

Source Code (.cpp)
      │
      ▼
1. Preprocessing   →  Handles # directives (#include, #define). Produces expanded source.
      │
      ▼
2. Compilation     →  Translates preprocessed code into Assembly code.
      │
      ▼
3. Assembly        →  Converts assembly into Object code (machine code, .o/.obj files).
      │
      ▼
4. Linking         →  Combines object files + libraries into a single executable.
      │
      ▼
Executable (.exe / a.out)

Step-by-step explanation:

  1. Preprocessing — The preprocessor scans for lines starting with # (like #include <iostream>) and textually substitutes/expands them before actual compilation begins. It does NOT understand C++ syntax — it's just text substitution.
  2. Compilation — The compiler (e.g., GCC, Clang, MSVC) checks syntax, performs type checking, and translates the code into assembly language specific to the target CPU architecture.
  3. Assembly — The assembler converts assembly code into binary object code (.o on Linux/Mac, .obj on Windows). This is machine code, but not yet a runnable program — function calls to external libraries aren't resolved yet.
  4. Linking — The linker resolves references between object files and libraries (like the C++ standard library), combining everything into a single executable binary.

Compiling from the command line (g++)

# Compile a single file into an executable
g++ main.cpp -o main

# Run it
./main          # Linux/Mac
main.exe        # Windows

# Compile with warnings enabled (recommended for learning)
g++ -Wall -Wextra main.cpp -o main

# Compile with a specific C++ standard
g++ -std=c++17 main.cpp -o main

Interview tip: If asked "What happens when you compile a C++ program?" — always mention all four stages (preprocessing → compilation → assembly → linking), not just "it turns into an exe."

3. The main() Function

Every C++ program must have exactly one main() function — it is the designated entry point where program execution begins.

#include <iostream>
using namespace std;

int main() {
    cout << "Hello, World!" << endl;
    return 0;
}

Breaking this down:

  • #include <iostream> — a preprocessor directive that includes the input/output stream library, giving us access to cin, cout, etc.
  • using namespace std; — brings all names from the std namespace into scope, so we can write cout instead of std::cout.
  • int main() — the function returns an int to the operating system.
  • return 0; — signals successful program termination to the OS. A non-zero return value conventionally signals an error occurred.
  • return 0; is technically optional in main() specifically (and only main()) — if omitted, the compiler implicitly returns 0. This is a special-case rule unique to main().

Valid signatures of main():

int main() { ... }                        // Most common
int main(void) { ... }                    // Equivalent to above (C-style)
int main(int argc, char* argv[]) { ... }  // Accepts command-line arguments
  • argc (argument count) — number of command-line arguments passed, including the program name itself.
  • argv (argument vector) — array of C-style strings containing the actual arguments.
#include <iostream>
using namespace std;

int main(int argc, char* argv[]) {
    cout << "Number of arguments: " << argc << endl;
    for (int i = 0; i < argc; i++) {
        cout << "Argument " << i << ": " << argv[i] << endl;
    }
    return 0;
}

4. Comments

Comments are ignored by the compiler entirely — they exist purely for human readers.

// This is a single-line comment

/*
   This is a
   multi-line comment
*/

int x = 5; // inline comment explaining this line

/* Multi-line comments CANNOT be nested:
   /* this will cause a compile error */
*/

Best practices:

  • Use comments to explain why, not what (the code already shows what it does).
  • Avoid over-commenting obvious code (x = x + 1; // increment x is redundant).
  • Use comments to document function purpose, edge cases handled, and assumptions.

5. Variables

A variable is a named location in memory used to store a value that can change during program execution.

Declaration & Initialization

int age;               // Declaration only — value is garbage/undefined
int age = 25;           // Declaration + initialization (copy-initialization)
int age(25);            // Direct initialization
int age{25};             // Brace/uniform initialization (C++11+, preferred — prevents narrowing)

int a, b, c;               // Multiple declarations
int a = 1, b = 2, c = 3;   // Multiple declarations with initialization

Why brace initialization {} is preferred (interview-relevant):

int x = 3.9;    // Compiles silently — x becomes 3 (data loss, "narrowing")
int y{3.9};      // Compile ERROR — narrowing conversion not allowed

Brace initialization catches accidental data-loss bugs at compile time.

Naming Rules

  • Must start with a letter or underscore (_), not a digit.
  • Can contain letters, digits, underscores only.
  • Case-sensitive (age and Age are different variables).
  • Cannot use C++ reserved keywords (int, class, return, etc.).
int _score;      // valid
int score2;      // valid
int 2score;      // INVALID — starts with digit
int my score;    // INVALID — contains space
int class;       // INVALID — reserved keyword

Scope of Variables

Scope typeWhere declaredLifetime
Local variableInside a function/block {}Created on entry, destroyed on exit of block
Global variableOutside all functionsExists for entire program runtime
Static local variableInside function, with static keywordPersists across function calls, initialized only once
 
#include <iostream>
using namespace std;

int globalVar = 100; // Global — accessible anywhere in this file

void counter() {
    static int callCount = 0; // Initialized once, retains value between calls
    callCount++;
    cout << "Called " << callCount << " times" << endl;
}

int main() {
    int localVar = 5; // Local to main only
    counter(); // Called 1 times
    counter(); // Called 2 times
    counter(); // Called 3 times
    return 0;
}

6. Constants

Constants are values that cannot be changed after initialization.

Using const

const double PI = 3.14159;
PI = 3.14; // Compile ERROR — cannot modify a const variable
  • Must be initialized at the time of declaration (you can't declare a const and assign later).
  • Enforced at compile time.

Using #define (macro constant — legacy C-style)

#define PI 3.14159
// The preprocessor textually replaces every occurrence of PI with 3.14159 before compilation

const vs #define — a classic interview question:

const#define
Type-safe (compiler checks types)No type checking — pure text substitution
Obeys scope rulesNo scope — applies globally wherever included
Visible to debuggerNot visible to debugger (already replaced by preprocessor)
Preferred in modern C++Avoid in modern C++ except for header guards

constexpr (C++11+)

constexpr int SIZE = 10; // Evaluated at COMPILE time, not runtime
int arr[SIZE]; // Valid — SIZE must be known at compile time for array size

constexpr guarantees the value is computed at compile time (useful for array sizes, template parameters), whereas plain const may be initialized at runtime.

int x;
cin >> x;
const int a = x;        // valid — const, but runtime-initialized
constexpr int b = x;    // COMPILE ERROR — x isn't known at compile time

Type Modifiers

signed int a;          // Can hold negative & positive (default for int)
unsigned int b;        // Only 0 and positive — doubles the positive range
short int c;           // Reduced size

unsigned long long e;  // Largest unsigned integer type

Interview trap: Unsigned integer underflow.

unsigned int x = 0;
x = x - 1;
cout << x; // Prints 4294967295 (wraps around!) — NOT -1

This is a very common source of bugs in competitive programming (e.g., looping for (unsigned int i = n-1; i >= 0; i--) when n = 0 causes infinite loop).

8. Type Conversion & Casting

Implicit Conversion (Type Coercion)

The compiler automatically converts one data type to another when needed, following a hierarchy (smaller → larger types is "safe"/widening).

int a = 10;
double b = a;      // int → double, implicit, safe (widening)
cout << b;          // 10

double x = 9.7;
int y = x;            // double → int, implicit, UNSAFE (narrowing) — truncates to 9
cout << y;             // 9 (not 10 — it truncates, doesn't round)

char c = 'A';
int ascii = c;          // char → int, implicit — gives ASCII value
cout << ascii;            // 65

Implicit conversion hierarchy (roughly, smaller to larger):
bool → char → short → int → long → long long → float → double → long double

Explicit Conversion (Casting)

When you deliberately force a conversion:

// C-style cast (inherited from C, discouraged in modern C++)
double pi = 3.14159;
int truncated = (int)pi; // truncated = 3

// Function-style cast
int truncated2 = int(pi);

// C++-style casts (preferred — covered in depth in Module 3.6)
int truncated3 = static_cast<int>(pi);

Why avoid C-style casts: They're "too powerful" — a single (int)x can silently perform static_cast, const_cast, or reinterpret_cast depending on context, making bugs harder to catch. Modern C++ prefers explicit static_cast<>, dynamic_cast<>, etc. (full deep-dive in Module 3.6).

Common Conversion Pitfalls (High interview relevance)

int a = 7, b = 2;
cout << a / b;              // 3 — integer division truncates!
cout << (double)a / b;      // 3.5 — casting ONE operand to double forces float division
cout << a / (double)b;      // 3.5 — same effect

float f = 0.1f + 0.2f;
cout << (f == 0.3f);        // Often FALSE — floating point precision issues!

9. Input / Output (I/O)

C++ uses streams for I/O, defined in <iostream>.

ObjectPurposeAssociated with
cinStandard inputKeyboard
coutStandard outputConsole/screen
cerrStandard error (unbuffered)Console/screen
clogStandard error (buffered)Console/screen

cout — Output

#include <iostream>
using namespace std;

int main() {
    int age = 21;
    cout << "Age: " << age << endl;        // endl flushes buffer + newline
    cout << "Age: " << age << "\n";          // "\n" is faster (no flush)
    cout << "A" << "B" << "C";                 // Chaining with <<
    return 0;
}

endl vs "\n" (common interview question): endl inserts a newline AND flushes the output buffer, which has a performance cost. "\n" just inserts a newline character. In performance-critical code (competitive programming), prefer "\n".

cin — Input

#include <iostream>
using namespace std;

int main() {
    int age;
    cout << "Enter your age: ";
    cin >> age;                    // Reads a single value

    int a, b;
    cin >> a >> b;                  // Reads multiple values, space/newline separated

    string name;
    cin >> name;                    // Reads a single WORD only (stops at whitespace)

    string fullLine;
    cin.ignore();                    // Clears leftover newline from buffer
    getline(cin, fullLine);           // Reads an ENTIRE line, including spaces

    cout << "Name: " << name << ", Age: " << age << endl;
    return 0;
}

Critical gotcha — mixing cin >> and getline():

int age;
string name;

cin >> age;              // Leaves a trailing '\n' in the input buffer
getline(cin, name);       // Immediately reads that leftover '\n' as an empty line!

// Fix:
cin >> age;
cin.ignore();              // Discard the leftover newline
getline(cin, name);         // Now works correctly

Faster I/O for Competitive Programming

ios_base::sync_with_stdio(false);
cin.tie(NULL);

This disables synchronization between C++ streams and C's stdio, and untangles cin from auto-flushing cout — significantly speeding up I/O for programs with heavy input/output (common first line in competitive programming templates).

10. Operators

Arithmetic Operators

int a = 10, b = 3;
cout << a + b << endl;   // 13
cout << a - b << endl;    // 7
cout << a * b << endl;     // 30
cout << a / b << endl;      // 3  (integer division — truncates)
cout << a % b << endl;       // 1  (modulo — remainder; undefined for floats without fmod)

Relational (Comparison) Operators

a == b   // Equal to
a != b   // Not equal to
a > b    // Greater than
a < b    // Less than
a >= b   // Greater than or equal to
a <= b   // Less than or equal to
// All return a bool: true(1) or false(0)

Logical Operators

bool p = true, q = false;
p && q   // Logical AND — true only if both true
p || q   // Logical OR — true if at least one true
!p       // Logical NOT — inverts the value

Short-circuit evaluation (important interview concept):

int x = 0;
if (x != 0 && (10 / x > 1)) { ... }
// Safe! Since x != 0 is false, (10/x) is NEVER evaluated — no division-by-zero crash.

Assignment Operators

int a = 10;
a += 5;   // a = a + 5  → 15
a -= 3;   // a = a - 3  → 12
a *= 2;   // a = a * 2  → 24
a /= 4;   // a = a / 4  → 6
a %= 4;   // a = a % 4  → 2

Increment / Decrement Operators

int a = 5;
cout << a++;   // Post-increment: prints 5, THEN a becomes 6
cout << a;      // 6

int b = 5;
cout << ++b;    // Pre-increment: b becomes 6 FIRST, then prints 6
cout << b;       // 6

Interview trap:

int i = 5;
int result = i++ + ++i;
// i++  → uses 5, i becomes 6
// ++i  → i becomes 7, uses 7
// result = 5 + 7 = 12, i = 7

(This exact expression is technically undefined behavior pre-C++17 due to unsequenced modifications, but interviewers often still ask it to test understanding of pre/post increment — worth mentioning both the "expected" trace AND the UB caveat.)

Bitwise Operators

int a = 5;   // 0101
int b = 3;    // 0011

cout << (a & b);   // AND  → 0001 = 1
cout << (a | b);    // OR   → 0111 = 7
cout << (a ^ b);     // XOR  → 0110 = 6
cout << (~a);          // NOT  → flips all bits → -6 (two's complement)
cout << (a << 1);       // Left shift → 1010 = 10 (multiply by 2)
cout << (a >> 1);        // Right shift → 0010 = 2 (divide by 2)

Bitwise operators are heavily used in Module 6.13 (Bit Manipulation patterns).

Ternary (Conditional) Operator

int a = 10, b = 20;
int max = (a > b) ? a : b;    // max = 20
// Equivalent to:
// if (a > b) max = a; else max = b;

sizeof Operator

cout << sizeof(int);      // 4
cout << sizeof(double);    // 8
int arr[10];
cout << sizeof(arr);       // 40 (10 * 4 bytes)

Coding

  1. Write a program that takes two integers as input and prints their sum, difference, product, quotient, and remainder — each on a separate line.
