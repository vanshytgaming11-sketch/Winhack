Module 1.5 — Pointers & References

Pointers and references are two of the most important — and most heavily interview-tested — features of C++. They give direct control over memory, enable efficient parameter passing, and underpin how dynamic memory, arrays, and many data structures work internally.

1. What Is a Pointer?

A pointer is a variable that stores the memory address of another variable, rather than a value directly. Every variable in a running program lives at some address in memory; a pointer "points to" that address. 

int x = 10;
int *p = &x;   // p stores the ADDRESS of x

cout << x;      // 10 — the value of x
cout << &x;      // some address like 0x7ffee3a1c8ac — address-of operator
cout << p;       // same address — p holds &x
cout << *p;       // 10 — dereference operator, gives the value AT that address

Declaring Pointers

int *p1;      // pointer to int
double *p2;    // pointer to double
char *p3;       // pointer to char

// The * can be placed next to the type or the variable name — purely stylistic,
// but be careful with multiple declarations on one line:
int* a, b;     // a is a pointer to int, but b is just a PLAIN int (common trap!)
int *a, *b;    // both a and b are pointers to int — safer style

2. Address-of (&) and Dereference (*) Operators

These two operators are central to pointer usage and are often confused because & and * mean different things depending on context.

OperatorContextMeaning
&Before a variable, in an expression"Address of" — gives the memory address of that variable
&In a type declaration, e.g. int &refDeclares a reference (not related to address-of here)
*In a declaration, e.g. int *pDeclares p as a pointer to int
*Before a pointer variable in an expression"Dereference" — gives the value stored at the address the pointer holds
 
int x = 5;
int *p = &x;

*p = 20;          // Dereference and assign — modifies x directly (x is now 20)
cout << x;         // 20

3. Pointer Arithmetic

Pointer arithmetic doesn't move by raw bytes — it moves by units of the pointed-to type's size. Adding 1 to an int* advances the address by sizeof(int) bytes (typically 4), not by 1 byte. 

int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;         // arr decays to a pointer to arr[0]; p == &arr[0]

cout << *p << endl;      // 10
cout << *(p + 1) << endl;  // 20 — moves forward by sizeof(int), lands on arr[1]
cout << *(p + 4) << endl;   // 50 — arr[4]

p++;                          // p now points to arr[1]
cout << *p << endl;             // 20

cout << p - arr << endl;         // 1 — pointer subtraction gives the number of ELEMENTS between them, not bytes

Array indexing is literally pointer arithmetic in disguise:

arr[i]     // is exactly equivalent to
*(arr + i)  // these two expressions are 100% interchangeable — a classic interview fact
// Which also means, surprisingly, this compiles and works:
i[arr]      // same as arr[i] — because *(arr + i) == *(i + arr)

4. `nullptr` and Uninitialized Pointers

int *p;         // UNINITIALIZED — points to garbage memory, dangerous to dereference
int *p = nullptr; // explicitly points to nothing (C++11+, preferred over C-style NULL)

if (p == nullptr) {
    cout << "p points to nothing" << endl;
}

int *q = NULL;     // legacy C-style null pointer — still works but nullptr is safer
                     // (nullptr has its own type, NULL is often just 0 or (void*)0)

Interview tip: Always initialize pointers — either to a valid address or to nullptr. Dereferencing an uninitialized ("wild") pointer is undefined behavior and a very common source of crashes.

5. References

A reference is an alias — an alternate name — for an already-existing variable. Unlike a pointer, it is not a separate object that stores an address; it directly refers to the same memory location as the original variable. 

int x = 10;
int &ref = x;    // ref is now another name for x

cout << ref;       // 10
ref = 20;            // modifies x directly
cout << x;             // 20 — x changed too, because ref IS x

int y = 30;
ref = y;                // this does NOT rebind ref to y!
                          // it copies y's VALUE into x (since ref still refers to x)
cout << x;                 // 30
cout << &x << " " << &ref;    // SAME address — proves ref and x are the same object

Rules for References

  • Must be initialized at the time of declaration — int &ref; alone is a compile error.
  • Cannot be "null" — a reference must always refer to a valid object.
  • Cannot be reseated — once bound to a variable, it can never refer to a different variable afterward.
  • No separate memory representation is guaranteed by the standard (conceptually, no "reference object" exists — it's just another name).
int &ref;         // COMPILE ERROR — references must be initialized
int &ref = 5;       // COMPILE ERROR — can't bind non-const reference to a literal/temporary
const int &ref = 5;  // VALID — const reference CAN bind to a temporary (extends its lifetime)

6. Pointers vs References — The Classic Interview Comparison

AspectPointerReference
Can be nullYes (nullptr)No — must always refer to a valid object
Can be reassignedYes — can point to a different variable laterNo — bound permanently at initialization
Needs initializationNo (dangerous, but legal to declare uninitialized)Yes — mandatory at declaration

7. Pointers with Arrays

Already previewed above, but formalized here — the deep relationship between arrays and pointers is a frequent interview topic.

int arr[5] = {1, 2, 3, 4, 5};
int *p = arr;              // no & needed — array name decays to pointer to first element

// These are all equivalent ways to access arr[2]:
cout << arr[2];              // 3
cout << *(arr + 2);            // 3
cout << p[2];                    // 3
cout << *(p + 2);                  // 3

Key distinction — array vs pointer:

int arr[5] = {1, 2, 3, 4, 5};
int *p = arr;

cout << sizeof(arr);  // 20 — size of the WHOLE array (5 * 4 bytes)
cout << sizeof(p);      // 8 (on a 64-bit system) — size of a POINTER, regardless of what it points to

// This is why sizeof(arr)/sizeof(arr[0]) only works on an actual array,
// NOT on a pointer that merely points to the first element (a very common bug
// when arrays are passed into functions — see below).

Arrays "decay" to pointers when passed to functions

void printSize(int arr[]) {
    cout << sizeof(arr); // 8 — arr is actually just a POINTER here, not the real array!
                            // This is a classic interview gotcha.
}

int main() {
    int arr[5] = {1, 2, 3, 4, 5};
    cout << sizeof(arr);   // 20 — correct size, in the scope where arr is a real array
    printSize(arr);           // but inside the function, it decays to int*, losing size info
    return 0;
}

This is exactly why array-processing functions in C++ typically require the size to be passed explicitly as a separate parameter — the array itself doesn't carry its length once it decays to a pointer. 

void printArray(int arr[], int size) {
    for (int i = 0; i < size; i++) {
        cout << arr[i] << " ";
    }
}

int main() {
    int arr[5] = {1, 2, 3, 4, 5};
    printArray(arr, 5);
    return 0;
}

8. Pointers to Pointers

A pointer can itself point to another pointer — useful in scenarios like dynamic 2D arrays or modifying a pointer's value inside a function.

int x = 10;
int *p = &x;
int **pp = &p;    // pp holds the address of p

cout << x;          // 10
cout << *p;           // 10
cout << **pp;           // 10 — double dereference

9. Dynamic Memory (preview — full depth in Module 2.1)

So far, all variables have been on the stack — automatically allocated and deallocated as functions enter/exit. Pointers also enable heap allocation, where memory persists until explicitly freed. This is fully covered in Module 2.1, but the basic syntax: 

int *p = new int;       // allocates a single int on the heap
*p = 42;
cout << *p;               // 42
delete p;                   // MUST manually free heap memory — no automatic cleanup

int *arr = new int[5];        // allocates an array of 5 ints on the heap
delete[] arr;                   // must use delete[] for arrays, not delete

Forgetting delete causes a memory leak — memory that stays reserved for the program's entire lifetime even though it's no longer needed. This entire topic (stack vs heap, leaks, dangling pointers) is explored in full depth next module.

10. Passing Pointers and References to Functions (recap & extension)

This connects directly back to Module 1.3 — here's the fuller picture with pointers included:

void modifyByPointer(int *p) {
    *p = 100;
}

void modifyByReference(int &r) {
    r = 200;
}

int main() {
    int a = 5, b = 5;

    modifyByPointer(&a);   // must pass address explicitly
    modifyByReference(b);    // pass variable directly, no & needed at call site

    cout << a << " " << b;     // 100 200
    return 0;
}

Why prefer references over pointers for function parameters (when nullability isn't needed): Cleaner call-site syntax (no &/* juggling), and references can't be null, so you don't need to defensively check for that inside the function.

Practice Questions

Conceptual

  1. Explain the difference between the & operator used in a declaration versus used in an expression.
  2. Why does p + 1 on an int* advance the address by 4 bytes rather than 1 byte? What determines this step size?
  3. List at least four differences between pointers and references. When would you strictly need a pointer instead of a reference?
  4. Explain why int* a, b; does NOT declare two pointers, and how to fix it.
  5. Why does sizeof(arr) give a different result inside a function that receives the array as a parameter, compared to the scope where the array was originally declared?

Coding

  1. Write a function void swap(int *a, int *b) that swaps two integers using pointers (not references).
  2. Write a program that uses pointer arithmetic (not array indexing syntax) to print all elements of an array and compute their sum.
  3. Write a function int* findMax(int arr[], int size) that returns a pointer to the largest element in the array, then dereference it in main() to print the value.
  4. Write a program demonstrating the difference between a pointer and a reference: create both pointing/referring to the same variable, reassign the pointer to a different variable, and attempt to explain (in a comment) why the same cannot be done with the reference.
  5. Write a function that takes an array and its size, and reverses the array in place using two pointers moving from opposite ends toward the middle.
