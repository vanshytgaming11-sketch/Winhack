Module 2.4 — OOP Principles

Object-Oriented Programming (OOP) rests on four foundational principles: Encapsulation, Inheritance, Polymorphism, and Abstraction. These aren't just C++ syntax features — they're a way of organizing code around real-world entities and their interactions, and interviewers frequently ask you to explain each with your own example.

1. Encapsulation

Encapsulation is the bundling of data and the functions that operate on it into a single unit (a class), while restricting direct access to the internal data — typically by making data members private and exposing controlled access through public member functions (getters/setters).

Why it matters: it protects an object's internal state from being put into an invalid condition by external code, and lets you change the internal implementation later without breaking code that uses the class.

class BankAccount {
    private:
        double balance;   // hidden — cannot be modified directly from outside

    public:
        BankAccount(double initial) : balance(initial) {}

        void deposit(double amount) {
            if (amount > 0) balance += amount; // validation enforced HERE, in one place
        }

        bool withdraw(double amount) {
            if (amount > 0 && amount <= balance) {
                balance -= amount;
                return true;
            }
            return false; // rejects invalid withdrawals
        }

        double getBalance() const {
            return balance;
        }
};

int main() {
    BankAccount acc(1000);
    acc.deposit(500);
    acc.withdraw(2000);      // rejected — insufficient funds, balance untouched
    // acc.balance = -999;    // COMPILE ERROR — can't bypass validation, balance is private
    cout << acc.getBalance(); // 1500
    return 0;
}

Without encapsulation, any code with access to a BankAccount object could set balance = -999; directly, bypassing all validation logic — encapsulation makes that impossible by construction.

2. Inheritance

Inheritance allows a new class (the derived/child class) to acquire the properties and behavior of an existing class (the base/parent class), while adding or overriding functionality. This models "is-a" relationships and enables code reuse. 

class Animal {
    public:
        string name;

        Animal(string n) : name(n) {}

        void eat() {
            cout << name << " is eating" << endl;
        }
};

class Dog : public Animal {   // Dog INHERITS from Animal — "a Dog IS AN Animal"
    public:
        Dog(string n) : Animal(n) {}  // must call base class constructor explicitly

        void bark() {
            cout << name << " says Woof!" << endl; // `name` is inherited from Animal
        }
};

int main() {
    Dog d("Rex");
    d.eat();     // inherited from Animal — "Rex is eating"
    d.bark();      // Dog's own method — "Rex says Woof!"
    return 0;
}

Types of Inheritance

TypeDescription
SingleOne derived class from one base class
MultipleOne derived class from two or more base classes
MultilevelA chain — C derives from B, B derives from A
HierarchicalMultiple derived classes from a single base class
HybridA combination of the above patterns
 
// Multilevel inheritance
class A { public: void showA() { cout << "A"; } };
class B : public A { public: void showB() { cout << "B"; } };
class C : public B { public: void showC() { cout << "C"; } };

int main() {
    C obj;
    obj.showA(); obj.showB(); obj.showC(); // ABC — C inherits from both A and B transitively
}

// Hierarchical inheritance
class Shape { public: void info() { cout << "I am a shape"; } };
class Circle : public Shape {};
class Square : public Shape {};
// Both Circle and Square inherit independently from Shape

Access Specifiers in Inheritance

The inheritance keyword (public, protected, or private) controls how the base class's members are exposed in the derived class:

public inheritance (by far the most common) models a true "is-a" relationship and is almost always what you want.

3. Polymorphism

Polymorphism ("many forms") means the same interface (function name/operator) can behave differently depending on context. C++ supports two kinds:

  • Compile-time polymorphism — resolved by the compiler before the program runs. Achieved via function overloading (Module 1.3) and operator overloading (Module 2.5).
  • Runtime polymorphism — resolved while the program is running, based on the actual object type. Achieved via virtual functions (full deep-dive in Module 2.5).

Compile-time Polymorphism (recap)

void print(int x)    { cout << "int: " << x; }
void print(double x)  { cout << "double: " << x; }
// The compiler decides WHICH print() to call based on argument type — decided at COMPILE time

Runtime Polymorphism (preview — full mechanics in Module 2.5)

class Animal {
    public:
        virtual void speak() {   // `virtual` enables runtime polymorphism
            cout << "Some generic animal sound" << endl;
        }
};

class Dog : public Animal {
    public:
        void speak() override {   // overrides the base class version
            cout << "Woof!" << endl;
        }
};

class Cat : public Animal {
    public:
        void speak() override {
            cout << "Meow!" << endl;
        }
};

int main() {
    Animal *a1 = new Dog();
    Animal *a2 = new Cat();

    a1->speak();  // "Woof!" — even though the pointer's declared type is Animal,
    a2->speak();   // "Meow!" — the ACTUAL object type determines which speak() runs, at RUNTIME

    delete a1;
    delete a2;
    return 0;
}

This is the essence of runtime polymorphism: the same call, ptr->speak(), produces different behavior depending on what object ptr actually points to — not what type it was declared as. The full mechanism (vtables, why virtual is required for this to work) is covered in depth in Module 2.5.

4. Abstraction

Abstraction means exposing only the essential, relevant details of an object while hiding the complex implementation details behind a simpler interface. Where encapsulation is about restricting access to data, abstraction is about simplifying what the user needs to think about.

Everyday analogy: driving a car requires knowing how to use the steering wheel, pedals, and gear stick — you don't need to understand the internal combustion engine or transmission mechanics to drive. The car's controls are an abstraction over its internal complexity.

class Car {
    private:
        void injectFuel() { /* complex internal detail */ }
        void igniteSpark() { /* complex internal detail */ }
        void engageTransmission() { /* complex internal detail */ }

    public:
        void start() {          // simple, abstracted interface exposed to the user
            injectFuel();
            igniteSpark();
            engageTransmission();
            cout << "Car started!" << endl;
        }
};

int main() {
    Car myCar;
    myCar.start();  // the USER only needs to know about start() — everything else is hidden
    return 0;
}

In C++, abstraction is achieved through access specifiers (hiding implementation details as private) and, more formally, through abstract classes and pure virtual functions, which define an interface without specifying implementation — covered fully in Module 2.5.

Practice Questions

Conceptual

  1. Explain encapsulation with an example different from the ones given above. Why does making data members private matter?
  2. What is the difference between compile-time and runtime polymorphism? Give one C++ mechanism for each.
  3. Explain the difference between encapsulation and abstraction — many people confuse these. Use your own analogy.
  4. What does public inheritance model conceptually? Why is it far more common than private or protected inheritance?
  5. In the runtime polymorphism example above, why does calling speak() through an Animal* pointer invoke the derived class's version instead of the base class's?

Coding

  1. Design a class hierarchy: a base class Vehicle with a name and a virtual function move(), and derived classes Car and Bike that override move() with their own message. Demonstrate runtime polymorphism using a Vehicle* pointer.
  2. Design an Employee class with private salary, exposing a public getter and a setter that rejects negative values — demonstrating encapsulation.
  3. Design a 3-level inheritance chain: LivingBeing → Animal → Dog, where each level adds one new member function, and demonstrate that a Dog object can call functions from all three levels.
  4. Design a simplified CoffeeMachine class that exposes only one public method brew(), internally calling several private helper methods (grindBeans(), heatWater(), pourWater()) — demonstrating abstraction.
