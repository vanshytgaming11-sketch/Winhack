Module 2.2 — Classes & Objects

A class is a user-defined blueprint (or template) that bundles data (attributes) and behavior (functions) together into a single unit. An object is a concrete instance created from that blueprint. Classes are the foundation of object-oriented programming in C++.

1. Defining a Class

class Student {
    public:
        string name;    // data member
        int age;          // data member

        void display() {  // member function
            cout << "Name: " << name << ", Age: " << age << endl;
        }
};

int main() {
    Student s1;          // creating an OBJECT (instance) of class Student
    s1.name = "Vinit";     // accessing data member using the dot operator
    s1.age = 22;
    s1.display();             // calling a member function
    return 0;
}

2. Data Members & Member Functions

Data members are the variables that hold an object's state. Member functions define the object's behavior — operations it can perform, usually on its own data members.

class Rectangle {
    public:
        double length;
        double width;

        double area() {
            return length * width;
        }

        double perimeter() {
            return 2 * (length + width);
        }
};

int main() {
    Rectangle r1;
    r1.length = 5.0;
    r1.width = 3.0;
    cout << "Area: " << r1.area() << endl;           // 15
    cout << "Perimeter: " << r1.perimeter() << endl;    // 16
    return 0;
}

3. Access Specifiers

Access specifiers control which parts of a class are visible from outside the class — this is the mechanism behind encapsulation (formalized in Module 2.4).

SpecifierAccessible from
publicAnywhere — inside the class, and from outside code using an object
privateOnly from within the class's own member functions (default for class)
protectedWithin the class, and derived classes (relevant once we cover inheritance — Module 2.4)
 
class BankAccount {
    private:
        double balance;   // hidden from outside — can't be accessed directly

    public:
        void deposit(double amount) {
            if (amount > 0) balance += amount;
        }

        double getBalance() {
            return balance;
        }
};

int main() {
    BankAccount acc;
    acc.deposit(1000);
    cout << acc.getBalance();  // 1000 — accessed via a public function
    // cout << acc.balance;    // COMPILE ERROR — balance is private, not directly accessible
    return 0;
}

class vs struct — the one real difference

struct Point {
    int x, y;   // PUBLIC by default in a struct
};

class Point2 {
    int x, y;   // PRIVATE by default in a class
};

Functionally, class and struct are otherwise identical in C++ (both can have member functions, constructors, inheritance, etc.) — the only difference is the default access specifier: public for struct, private for class. By convention, struct is used for simple data-holding types, and class for types with behavior and invariants to protect.

4. The this Pointer

Inside any non-static member function, this is an implicit pointer to the object on which the function was called. It's most commonly needed when a parameter name shadows a data member name. 

class Point {
    public:
        int x, y;

        void setX(int x) {
            this->x = x;   // `this->x` refers to the MEMBER, `x` (unqualified) refers to the PARAMETER
        }
};

int main() {
    Point p;
    p.setX(10);
    cout << p.x; // 10
    return 0;
}

this is also used to return the current object by reference, enabling method chaining:

class Builder {
    public:
        int value = 0;
        Builder& add(int v) {
            value += v;
            return *this; // returns a reference to the current object
        }
};

int main() {
    Builder b;
    b.add(5).add(10).add(2); // chained calls — each returns *this
    cout << b.value; // 17
    return 0;
}

5. Constructors

A constructor is a special member function, automatically called when an object is created, typically used to initialize data members. It has the exact same name as the class and no return type (not even void).

Default Constructor

class Student {
    public:
        string name;
        int age;

        Student() {                 // default constructor — no parameters
            name = "Unknown";
            age = 0;
            cout << "Default constructor called" << endl;
        }
};

int main() {
    Student s1; // constructor called automatically here
    cout << s1.name << " " << s1.age; // Unknown 0
    return 0;
}

Parameterized Constructor

class Student {
    public:
        string name;
        int age;

        Student(string n, int a) {
            name = n;
            age = a;
        }
};

int main() {
    Student s1("Vinit", 22);   // parameterized construction
    Student s2 = Student("Aman", 20); // equivalent alternate syntax
    cout << s1.name << " " << s1.age;
    return 0;
}

Constructor Initializer List (preferred, more efficient)

class Student {
    public:
        string name;
        int age;

        Student(string n, int a) : name(n), age(a) {  // initializer list
            // body can be empty, or contain additional logic
        }
};

The initializer list directly initializes members (calling their constructors with the given values), whereas assigning inside the body first default-constructs them and then assigns — an extra, wasted step for non-trivial types like string. For members that are const or references, the initializer list is not just preferred but mandatory, since they cannot be assigned to after construction. 

class Circle {
    public:
        const double PI;   // const member — MUST be set via initializer list
        double radius;

        Circle(double r) : PI(3.14159), radius(r) {}
};

Constructor Overloading

Like regular functions, constructors can be overloaded — a class can have multiple constructors with different parameter lists.

class Box {
    public:
        double length, width, height;

        Box() : length(1), width(1), height(1) {}                    // default
        Box(double side) : length(side), width(side), height(side) {} // cube
        Box(double l, double w, double h) : length(l), width(w), height(h) {} // full

        double volume() { return length * width * height; }
};

int main() {
    Box b1;              // uses default constructor → volume 1
    Box b2(5);             // uses single-param constructor → volume 125
    Box b3(2, 3, 4);         // uses 3-param constructor → volume 24
    cout << b1.volume() << " " << b2.volume() << " " << b3.volume();
    return 0;
}

6. Destructors

A destructor is a special member function automatically called when an object is destroyed — either when it goes out of scope (stack object) or when explicitly deleted (heap object). Its main use is releasing resources the object acquired (dynamically allocated memory, file handles, etc.). 

class Student {
    public:
        string name;

        Student(string n) : name(n) {
            cout << name << " constructed" << endl;
        }

        ~Student() {   // destructor — name preceded by ~, no parameters, no return type
            cout << name << " destroyed" << endl;
        }
};

int main() {
    {
        Student s("Vinit");   // constructor runs: "Vinit constructed"
    }                            // s goes out of scope here: "Vinit destroyed" prints automatically
    cout << "After block" << endl;
    return 0;
}
// Output:
// Vinit constructed
// Vinit destroyed
// After block

Destructors and Dynamic Memory

class IntArray {
    public:
        int *data;
        int size;

        IntArray(int s) : size(s) {
            data = new int[size];   // resource acquired in constructor
        }

        ~IntArray() {
            delete[] data;             // resource released in destructor — RAII pattern (Module 5.3)
            cout << "Memory freed" << endl;
        }
};

int main() {
    IntArray arr(10);
    // no need to manually delete arr.data — the destructor handles it automatically
    // when arr goes out of scope at the end of main()
    return 0;
}

This pattern — acquiring a resource in the constructor and releasing it in the destructor — is called RAII (Resource Acquisition Is Initialization), a foundational C++ idiom explored fully in Module 5.3 alongside smart pointers.

Rules about Destructors

  • A class has exactly one destructor (cannot be overloaded — it takes no parameters).
  • Called automatically — never called directly by name (except via delete for heap objects, which invokes it internally).
  • If not explicitly defined, the compiler generates a default (empty) one.
  • Should be declared virtual in base classes intended for polymorphic use — deep-dive in Module 2.5.
