Module 2.3 — Copying Objects

When one object is used to initialize or assign to another, C++ needs to decide how to copy its data members. By default, the compiler generates a copy constructor and copy assignment operator that do this member-by-member — but for classes managing dynamically allocated resources, the default behavior is dangerously wrong, which is exactly why this topic is a favorite in interviews.

1. Copy Constructor

A copy constructor initializes a new object as a copy of an existing object of the same class. It's invoked in these situations:

  • When an object is initialized from another: Student s2 = s1; or Student s2(s1);
  • When an object is passed by value to a function
  • When an object is returned by value from a function (though often elided — see Module 5.5)
class Student {
    public:
        string name;
        int age;

        Student(string n, int a) : name(n), age(a) {}

        // Copy constructor — compiler-provided by default, but can be written explicitly:
        Student(const Student &other) {
            name = other.name;
            age = other.age;
            cout << "Copy constructor called" << endl;
        }
};

int main() {
    Student s1("Vinit", 22);
    Student s2 = s1;          // copy constructor called
    Student s3(s1);             // also copy constructor

    s2.name = "Changed";
    cout << s1.name << " " << s2.name; // Vinit Changed — s1 unaffected, s2 is an independent copy
    return 0;
}

Note the signature: the parameter is always const ClassName & — a const reference, never by value. Passing by value would itself require making a copy to invoke the function, causing infinite recursion.

2. Copy Assignment Operator

While the copy constructor handles creation of a new object from an existing one, the copy assignment operator (operator=) handles assigning one already-existing object's contents to another already-existing object. 

class Student {
    public:
        string name;
        int age;

        Student(string n, int a) : name(n), age(a) {}

        Student& operator=(const Student &other) {
            if (this == &other) return *this; // self-assignment check — see below
            name = other.name;
            age = other.age;
            cout << "Copy assignment called" << endl;
            return *this;
        }
};

int main() {
    Student s1("Vinit", 22);
    Student s2("Aman", 20);

    s2 = s1;   // copy ASSIGNMENT called — s2 already exists, being overwritten
    cout << s2.name; // Vinit
    return 0;
}

Copy Constructor vs Copy Assignment — how to tell them apart

Student s1("Vinit", 22);
Student s2 = s1;     // COPY CONSTRUCTOR — s2 doesn't exist yet, being CREATED from s1
Student s3("X", 0);
s3 = s1;                // COPY ASSIGNMENT — s3 already exists, being OVERWRITTEN with s1's data

Rule of thumb: if the destination object is being created right now (declaration + initialization), it's the copy constructor. If the destination object already exists and is being assigned a new value afterward, it's copy assignment.

3. Shallow Copy vs Deep Copy

This is the single most important concept in this module. The compiler-generated default copy constructor/assignment perform a shallow copy — they copy each member's value directly, byte for byte. For pointer members, this copies the pointer itself (the address), not the memory it points to. This becomes a serious bug when a class manages heap-allocated resources.

The Problem — Shallow Copy of a Pointer Member

class IntArray {
    public:
        int *data;
        int size;

        IntArray(int s) : size(s) {
            data = new int[size];
            for (int i = 0; i < size; i++) data[i] = 0;
        }

        ~IntArray() {
            delete[] data;
        }
        // NO custom copy constructor defined — compiler generates a SHALLOW one
};

int main() {
    IntArray a(5);
    IntArray b = a;      // shallow copy — b.data now points to the SAME memory as a.data!

    b.data[0] = 99;         // modifies through b's pointer...
    cout << a.data[0];        // ...but a.data[0] ALSO shows 99! They share the same memory.

    // WORSE: when main() ends, BOTH a's and b's destructors run,
    // and BOTH call delete[] on the SAME memory address — this is a DOUBLE FREE,
    // which is undefined behavior and often crashes the program.
    return 0;
}

This diagram shows what a shallow copy actually does:

Before copy:
  a.data ──────► [heap block #1: 0 0 0 0 0]

After "IntArray b = a;" (SHALLOW COPY):
  a.data ──────► [heap block #1: 0 0 0 0 0]
  b.data ──────┘   (both pointers point to the SAME block — no new memory allocated for b)

The Fix — Deep Copy

A deep copy allocates separate, independent memory for the new object and copies the actual data values into it — not just the pointer.

class IntArray {
    public:
        int *data;
        int size;

        IntArray(int s) : size(s) {
            data = new int[size];
            for (int i = 0; i < size; i++) data[i] = 0;
        }

        // DEEP COPY constructor
        IntArray(const IntArray &other) : size(other.size) {
            data = new int[size];                  // allocate SEPARATE, NEW memory
            for (int i = 0; i < size; i++) {
                data[i] = other.data[i];              // copy VALUES, not the pointer
            }
        }

        // DEEP COPY assignment
        IntArray& operator=(const IntArray &other) {
            if (this == &other) return *this;       // self-assignment guard

            delete[] data;                             // free existing memory first
            size = other.size;
            data = new int[size];                        // allocate new memory
            for (int i = 0; i < size; i++) {
                data[i] = other.data[i];
            }
            return *this;
        }

        ~IntArray() {
            delete[] data;
        }
};

int main() {
    IntArray a(5);
    IntArray b = a;      // DEEP copy constructor — b.data is now a SEPARATE block

    b.data[0] = 99;
    cout << a.data[0];      // 0 — unaffected, because a and b now own independent memory

    // Destructors of a and b each delete[] their OWN separate memory — no double free
    return 0;
}

After the fix:

After "IntArray b = a;" (DEEP COPY):
  a.data ──────► [heap block #1: 0 0 0 0 0]
  b.data ──────► [heap block #2: 0 0 0 0 0]   (a completely separate, independently owned copy)

4. The Self-Assignment Check

In the copy assignment operator, always guard against obj = obj; (assigning an object to itself). Without the check, delete[] data; would free the memory before the subsequent lines try to read other.data[i] — but since other IS *this in a self-assignment, you'd be reading from memory you just freed. 

IntArray& operator=(const IntArray &other) {
    if (this == &other) return *this;  // guards against a = a;
    // ... rest of deep copy logic
}

5. Shallow Copy Is NOT Always Wrong

For classes whose members are all value types (int, double, string — which manage their own deep-copying internally) and contain no raw owning pointers, the compiler-generated shallow copy is perfectly correct and efficient. Deep copy is only necessary when the class directly owns a raw pointer (or other resource handle) that requires exclusive management. 

class Point {
    public:
        int x, y;   // plain value types — default (shallow) copy is completely safe and correct here
};

int main() {
    Point p1{1, 2};
    Point p2 = p1;    // compiler's default copy is fine — no shared ownership issue
    return 0;
}
