Module 2.5 — Advanced OOP

This module goes deeper into the mechanics behind runtime polymorphism (virtual functions, vtables), abstract classes, operator overloading, and two special access mechanisms: friend and static members. These are consistently among the most-asked C++ interview topics beyond the basics.

1. Function Overriding

Overriding occurs when a derived class provides its own implementation of a function that already exists in its base class, with the exact same signature (name, parameters, and const-ness). 

class Animal {
    public:
        void speak() {
            cout << "Generic animal sound" << endl;
        }
};

class Dog : public Animal {
    public:
        void speak() {                 // overrides Animal's speak()
            cout << "Woof!" << endl;
        }
};

int main() {
    Dog d;
    d.speak();  // "Woof!" — Dog's own version is used
    return 0;
}

But this alone is NOT enough for polymorphism through base-class pointers — that's exactly the gap virtual fills, shown next.

2. Virtual Functions and Why They're Needed

Without virtual, calling an overridden function through a base-class pointer/reference uses the static (declared) type of the pointer, not the actual object's type — this is called "static binding" and usually isn't what you want:

class Animal {
    public:
        void speak() {  // NOT virtual
            cout << "Generic animal sound" << endl;
        }
};

class Dog : public Animal {
    public:
        void speak() {
            cout << "Woof!" << endl;
        }
};

int main() {
    Animal *a = new Dog();
    a->speak();  // "Generic animal sound" — WRONG (from the caller's likely intent)!
                    // Because speak() is not virtual, the compiler resolves the call
                    // based on the POINTER's type (Animal*), not the actual object (Dog).
    delete a;
    return 0;
}

The Fix — Declaring virtual

class Animal {
    public:
        virtual void speak() {   // virtual enables dynamic (runtime) binding
            cout << "Generic animal sound" << endl;
        }
};

class Dog : public Animal {
    public:
        void speak() override {  // `override` (C++11+) is optional but strongly recommended —
                                    // it makes the compiler verify this actually overrides a base virtual function
            cout << "Woof!" << endl;
        }
};

int main() {
    Animal *a = new Dog();
    a->speak();  // "Woof!" — CORRECT — resolved at RUNTIME based on the actual object type
    delete a;
    return 0;
}

Why override Matters

class Animal {
    public:
        virtual void speak(int volume) { cout << "..."; }
};

class Dog : public Animal {
    public:
        void speak(double volume) override { cout << "Woof"; }
        // COMPILE ERROR with override — this does NOT actually override speak(int),
        // it's a completely different overload (parameter type mismatch: double vs int).
        // Without `override`, this bug would compile silently and cause confusing behavior.
};

How It Works Internally — the Vtable (conceptual, common interview question)

When a class has at least one virtual function, the compiler generates a hidden virtual table (vtable) — essentially an array of function pointers, one per virtual function, specific to that class. Every object of that class carries a hidden pointer (vptr) to its class's vtable. A call through a base pointer looks up the actual function to run via this vptr/vtable at runtime, rather than being hard-wired at compile time — this indirection is what enables dynamic dispatch, and also why virtual calls have a small (usually negligible) performance overhead compared to non-virtual calls.

3. Pure Virtual Functions & Abstract Classes

A pure virtual function has no implementation in the base class — it's declared with = 0, and forces every derived class to provide its own implementation. A class containing at least one pure virtual function becomes an abstract class — it cannot be instantiated directly; it can only serve as a base class. 

class Shape {
    public:
        virtual double area() = 0;    // PURE virtual function — no body, ends with = 0
        virtual void display() {         // regular virtual function — CAN have a default body
            cout << "Area: " << area() << endl; // calls the derived class's area() via polymorphism
        }
};

class Circle : public Shape {
    public:
        double radius;
        Circle(double r) : radius(r) {}
        double area() override {           // MUST implement area() — required by the abstract base
            return 3.14159 * radius * radius;
        }
};

class Square : public Shape {
    public:
        double side;
        Square(double s) : side(s) {}
        double area() override {
            return side * side;
        }
};

int main() {
    // Shape s;                // COMPILE ERROR — cannot instantiate an abstract class
    Shape *shapes[2];
    shapes[0] = new Circle(5);
    shapes[1] = new Square(4);

    for (int i = 0; i < 2; i++) {
        shapes[i]->display();    // polymorphic call — each prints its own correct area
    }

    delete shapes[0];
    delete shapes[1];
    return 0;
}

An abstract class effectively defines an interface or contract: "any class that wants to be a Shape MUST provide an area() implementation." This is a direct, formal mechanism for the abstraction principle introduced in Module 2.4.

4. Virtual Destructors (critical, frequently missed)

If a base class is meant to be used polymorphically (deleted through a base-class pointer), its destructor must be declared virtual — otherwise deleting a derived object through a base pointer only calls the base class's destructor, leaking any resources the derived class allocated. 

class Base {
    public:
        ~Base() {                // NOT virtual — BUG waiting to happen
            cout << "Base destructor" << endl;
        }
};

class Derived : public Base {
    public:
        int *data;
        Derived() { data = new int[100]; }
        ~Derived() {
            delete[] data;
            cout << "Derived destructor" << endl;
        }
};

int main() {
    Base *b = new Derived();
    delete b;   // Only "Base destructor" prints — Derived's destructor is SKIPPED!
                  // data (the heap array) is LEAKED, because ~Derived() never ran.
    return 0;
}

Fix:

class Base {
    public:
        virtual ~Base() {   // virtual destructor — ensures correct cleanup chain
            cout << "Base destructor" << endl;
        }
};
// Now: delete b; correctly calls ~Derived() first, then ~Base() — no leak.

Rule of thumb: if a class has any virtual function, or is ever intended to be used as a polymorphic base class, give it a virtual destructor.

5. Operator Overloading

C++ allows most built-in operators (+, -, ==, <<, etc.) to be redefined for user-defined types, so objects of your classes can be used with natural, intuitive syntax. 

class Point {
    public:
        int x, y;
        Point(int x = 0, int y = 0) : x(x), y(y) {}

        // Overload + as a member function
        Point operator+(const Point &other) {
            return Point(x + other.x, y + other.y);
        }

        // Overload == as a member function
        bool operator==(const Point &other) {
            return x == other.x && y == other.y;
        }
};

int main() {
    Point p1(1, 2), p2(3, 4);
    Point p3 = p1 + p2;      // calls operator+ → Point(4, 6)
    cout << p3.x << " " << p3.y;  // 4 6

    cout << (p1 == p2);        // 0 (false) — calls operator==
    return 0;
}

Overloading << for cout (must be a non-member/friend function)

class Point {
    public:
        int x, y;
        Point(int x, int y) : x(x), y(y) {}

        // Declared as a FRIEND so it can access private members if needed,
        // and as a NON-member because the left operand (ostream&) isn't a Point
        friend ostream& operator<<(ostream &out, const Point &p);
};

ostream& operator<<(ostream &out, const Point &p) {
    out << "(" << p.x << ", " << p.y << ")";
    return out;   // return by reference to allow chaining: cout << p1 << p2;
}

int main() {
    Point p(3, 4);
    cout << p;   // (3, 4) — natural, readable syntax enabled by operator overloading
    return 0;
}

Why << must be a non-member function: for a member function, the object on the left of the operator must be an instance of the class. But in cout << p, the left operand is cout (an ostream), not a Point — so it can't be a member of Point. It must be a free function (optionally a friend, if it needs private access).

6. Friend Functions and Friend Classes

A friend function or class is granted access to the private and protected members of the class that declares it as a friend — even though it isn't a member itself. Friendship must be explicitly granted; it is not inherited and not mutual. 

class Box {
    private:
        double width;

    public:
        Box(double w) : width(w) {}

        friend void printWidth(const Box &b);  // grants access to this specific function
};

void printWidth(const Box &b) {
    cout << "Width: " << b.width;  // can access PRIVATE member `width` — allowed because of friend
}

int main() {
    Box b(10.5);
    printWidth(b);
    return 0;
}

Friend Class

class Engine {
    private:
        int horsepower = 300;
        friend class Car;   // Car gets access to ALL private members of Engine
};

class Car {
    public:
        void showEnginePower(Engine &e) {
            cout << e.horsepower;  // allowed — Car is a friend of Engine
        }
};

Use sparingly: friendship breaks encapsulation, so it should be reserved for tightly-coupled cases (like operator overloading needing private access) rather than general-purpose convenience.

7. Static Members

A static data member is shared by all objects of a class — there's exactly one copy, regardless of how many objects exist. A static member function can be called without any object instance, and can only access other static members (it has no this pointer). 

class Counter {
    public:
        static int count;   // declaration — shared across ALL objects

        Counter() {
            count++;          // every new object increments the SAME shared counter
        }

        static int getCount() {   // static member function — no `this`, callable without an object
            return count;
        }
};

int Counter::count = 0;    // MUST define/initialize static members outside the class

int main() {
    Counter c1, c2, c3;
    cout << Counter::getCount();  // 3 — called via class name, not an object
    cout << c1.count;               // 3 — also accessible via an object, but still the SAME shared value
    return 0;
}

Key rules:

  • Static data members must be defined (and initialized) exactly once outside the class, in a .cpp file (except static constexpr, which can be initialized in-class).
  • Static member functions cannot access non-static (instance) members directly, since they have no specific object to work on — no this pointer exists inside them.
  • A common real use case: tracking how many objects of a class currently exist, or shared configuration/constants across all instances.
