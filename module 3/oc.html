Module 3.7 — Other Concepts

This module consolidates a few remaining foundational ideas — deeper uses of const, a full recap of static across all its contexts, and a summary of memory-related concepts that tie together everything covered so far in Modules 1–3.

1. const — The Full Picture

Module 1.1 introduced const for simple variables. Here's every context where const appears in C++, since interviewers frequently probe multiple forms in one question.

const Variables (recap)

const int MAX = 100;   // cannot be reassigned after initialization

const Pointers — Four Distinct Meanings

This is one of the trickiest and most frequently tested pointer topics:

int x = 10, y = 20;

int *p1 = &x;                     // plain pointer — both pointer and pointee are mutable
*p1 = 15;                            // OK — can modify the value
p1 = &y;                               // OK — can repoint

const int *p2 = &x;                 // pointer to CONST int — pointee is read-only THROUGH this pointer
// *p2 = 15;                            // COMPILE ERROR — cannot modify *p2
p2 = &y;                                // OK — can still repoint p2 itself

int *const p3 = &x;                  // CONST pointer to int — pointer itself cannot be reseated
*p3 = 15;                               // OK — can still modify the pointee
// p3 = &y;                               // COMPILE ERROR — cannot repoint a const pointer

const int *const p4 = &x;               // CONST pointer to CONST int — neither can change
// *p4 = 15;                                // COMPILE ERROR
// p4 = &y;                                   // COMPILE ERROR

Reading trick (right-to-left from the variable name): read the declaration starting at the variable name and moving outward/leftward.

DeclarationRead as
const int *p"p is a pointer to a const int" — pointee is const
int *const p"p is a const pointer to int" — pointer itself is const
const int *const p"p is a const pointer to a const int" — both are const

Note: const int *p and int const *p are exactly equivalent — the const can be written on either side of the type it modifies.

const with Function Parameters (recap from Module 1.3)

void printName(const string &name) {   // guarantees the function won't modify the caller's data
    cout << name;
}

const Member Functions

A member function marked const promises not to modify the object's data members — it can only be called on const objects/references, and the compiler enforces the promise. 

class Point {
    private:
        int x, y;
    public:
        Point(int x, int y) : x(x), y(y) {}

        int getX() const {     // const member function — promises not to modify the object
            return x;
            // x = 100;         // COMPILE ERROR if uncommented — const functions can't modify members
        }

        void setX(int newX) {   // NOT const — this one is ALLOWED to modify
            x = newX;
        }
};

void printX(const Point &p) {
    cout << p.getX();   // OK — getX() is const, so it CAN be called on a const reference
    // p.setX(5);           // COMPILE ERROR — setX() is non-const, cannot be called on a const object
}

Best practice: mark every member function const if it genuinely doesn't modify the object — this maximizes how flexibly the function can be used (e.g., callable on const references, as shown above) and communicates intent clearly.

3. Memory Concepts — Full-Module Recap

This section ties together memory-related ideas from across Modules 1–3 into one consolidated reference.

ConceptSummary
Stack memoryAutomatic allocation/deallocation, tied to scope, fast, limited size
Heap memoryManual allocation via new/delete, persists until freed, larger, slower
Memory leakHeap memory allocated but never freed, and no pointer remains to free it later
Dangling pointerPointer referencing memory that has already been freed or gone out of scope
Shallow vs deep copyShallow copies the pointer (shared ownership bug); deep copies the pointed-to data (safe, independent)
RAIIAcquiring a resource in a constructor and releasing it in a destructor, so cleanup happens automatically via scope
Global variablesExist for the entire program's runtime, accessible anywhere in the file (or program, if not static)

4. Mutable Keyword (bonus, less common but occasionally asked)

mutable allows a specific data member to be modified even from within a const member function — an intentional, narrow exception to const-correctness, typically used for internal bookkeeping (like caching or access counters) that shouldn't affect an object's externally observable state. 

class Logger {
    private:
        mutable int accessCount = 0;   // can be modified even in const functions

    public:
        void log() const {
            accessCount++;                // allowed — accessCount is mutable
            cout << "Access #" << accessCount << endl;
        }
};

int main() {
    const Logger l;
    l.log(); // Access #1 — works despite l being const, and log() being a const function
    l.log();  // Access #2
    return 0;
}
