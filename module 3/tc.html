Module 3.6 — Type Casting

Module 1.1 introduced casting briefly using C-style casts. C++ provides four distinct, purpose-specific casting operators that are safer and more explicit about programmer intent — the compiler can catch more mistakes when it knows exactly what kind of conversion you mean to perform. This is one of the most reliably asked topics in C++ interviews.

1. Why Not Just Use C-Style Casts?

double pi = 3.14159;
int x = (int)pi;   // C-style cast — works, but ambiguous about WHAT KIND of cast is happening
                       // Depending on context, a C-style cast can silently perform
                       // a static_cast, const_cast, or even reinterpret_cast —
                       // making dangerous conversions easy to write by accident.

C++'s four named casts make the kind of conversion explicit in the code itself, are easier to search for in a codebase, and some (like dynamic_cast) provide safety checks that a C-style cast cannot.

2. static_cast

The most commonly used cast — for well-defined, "sensible" conversions between related types: numeric conversions, pointer conversions within an inheritance hierarchy (without runtime checking), and explicit constructor/conversion-operator invocation. 

double pi = 3.14159;
int x = static_cast<int>(pi);      // 3 — numeric narrowing, explicit and clear intent

int a = 65;
char c = static_cast<char>(a);        // 'A' — int to char

float f = static_cast<float>(a) / 2;    // forces float division, avoids integer truncation

class Animal {};
class Dog : public Animal {};
Animal *animalPtr = new Dog();
Dog *dogPtr = static_cast<Dog*>(animalPtr); // downcast — NO runtime check; programmer asserts this is safe

Key characteristic: static_cast is checked at compile time only — it does not verify at runtime whether a downcast (base → derived) is actually valid. If you're wrong about the actual object type, this becomes undefined behavior. For downcasts where you're not 100% certain, use dynamic_cast instead.

3. dynamic_cast

Used specifically for safe downcasting within polymorphic class hierarchies (the base class must have at least one virtual function). Unlike static_cast, it performs a runtime check and returns nullptr (for pointers) or throws std::bad_cast (for references) if the cast is invalid. 

class Animal {
    public:
        virtual ~Animal() {}   // MUST have at least one virtual function for dynamic_cast to work
};

class Dog : public Animal {
    public:
        void bark() { cout << "Woof!"; }
};

class Cat : public Animal {};

int main() {
    Animal *a1 = new Dog();
    Animal *a2 = new Cat();

    Dog *d1 = dynamic_cast<Dog*>(a1);   // succeeds — a1 actually IS a Dog
    if (d1) {
        d1->bark(); // Woof!
    }

    Dog *d2 = dynamic_cast<Dog*>(a2);   // FAILS — a2 is a Cat, not a Dog
    if (d2 == nullptr) {
        cout << "Cast failed — a2 is not a Dog" << endl; // this runs
    }

    delete a1;
    delete a2;
    return 0;
}

Why the base class needs a virtual function: dynamic_cast relies on runtime type information (RTTI), which is only generated for polymorphic classes (those with a vtable, from Module 2.5). Attempting dynamic_cast on a non-polymorphic class hierarchy is a compile error.

4. const_cast

Used to add or remove the const (or volatile) qualifier from a variable. This is the only named cast that can do this — and it should be used sparingly, since modifying something that was declared const for genuinely good reasons is a design smell. 

void printValue(int *p) {
    cout << *p;
}

int main() {
    const int x = 10;
    // printValue(&x);                       // COMPILE ERROR — can't pass const int* as int*
    printValue(const_cast<int*>(&x));           // compiles — strips the const qualifier

    return 0;
}

The real danger — modifying a truly const object is undefined behavior:

const int x = 10;
int *p = const_cast<int*>(&x);
*p = 20;                            // UNDEFINED BEHAVIOR — x was declared genuinely const;
                                       // the compiler may have placed it in read-only memory,
                                       // or optimized assuming it never changes.
cout << x;                             // might print 10 (old, cached) OR 20 OR crash — unpredictable

const_cast is legitimately safe only when the underlying object was not actually declared const to begin with (e.g., calling a poorly-designed legacy function that takes a non-const pointer but doesn't actually modify the data). Using it to bypass const-correctness on a truly const object is a bug, not a feature.

5. reinterpret_cast

The most dangerous and least restricted cast — it reinterprets the raw bits of one type as a completely unrelated type, with essentially no safety checks. Used only for low-level operations: pointer-to-integer conversions, interfacing with hardware/OS-level APIs, or converting between unrelated pointer types. 

int x = 65;
int *p = &x;

// Reinterpreting the SAME memory address as a completely different type
char *charPtr = reinterpret_cast<char*>(p);
cout << *charPtr;   // interprets the first byte of x's memory as a char — platform/endianness dependent!

// Converting a pointer to an integer (to print its raw numeric address value)
uintptr_t addr = reinterpret_cast<uintptr_t>(p);
cout << addr;

Interview-relevant rule of thumb: if you find yourself reaching for reinterpret_cast in typical application-level code, it's almost always a sign of a design problem elsewhere — this cast belongs in systems programming, embedded contexts, or serialization code, not everyday logic.

Practice Questions

Conceptual

  1. Why are the four named C++ casts generally preferred over C-style casts?
  2. Why does dynamic_cast require the base class to have at least one virtual function?
  3. Explain the danger of using const_cast to modify an object that was genuinely declared const, versus using it on a non-const object passed through a poorly-typed legacy function.
  4. Why is reinterpret_cast considered the most dangerous of the four casts?
  5. What is the key behavioral difference between static_cast and dynamic_cast when downcasting an incorrect type?

Coding

  1. Write a base class Shape (with a virtual destructor) and derived classes Circle and Square. Write a function that takes a Shape* and uses dynamic_cast to safely determine and print which specific type it actually is.
  2. Demonstrate a correct, safe use of static_cast for numeric conversion (e.g., converting user input from double to int for array indexing), including a comment explaining why static_cast (not dynamic_cast) is appropriate here.
  3. Write a small program demonstrating const_cast being used to call a legacy function void oldPrint(char* msg) (which doesn't actually modify its argument) with a const char* string.
