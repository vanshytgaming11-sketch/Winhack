Module 3.3 — File Handling

C++ provides file I/O through the <fstream> library, which extends the same stream-based paradigm used for cin/cout to reading from and writing to files on disk.

1. The Three Stream Classes

ClassPurpose
ofstreamOutput file stream — for WRITING to files
ifstreamInput file stream — for READING from files
fstreamCombined stream — for BOTH reading and writing to the same file

2. Writing to a File

#include <fstream>
using namespace std;

int main() {
    ofstream outFile("data.txt");   // opens (creates if not existing) data.txt for writing

    if (!outFile) {                    // ALWAYS check the stream opened successfully
        cout << "Failed to open file" << endl;
        return 1;
    }

    outFile << "Hello, File!" << endl;   // same << syntax as cout, just writes to the file instead
    outFile << "Second line" << endl;

    outFile.close();                       // closes the file, flushing any buffered data to disk
    return 0;
}

Important: by default, ofstream truncates (erases) the file's existing content when opened this way — see file modes below to control this.

3. Reading from a File

#include <fstream>
#include <string>
using namespace std;

int main() {
    ifstream inFile("data.txt");

    if (!inFile) {
        cout << "Failed to open file" << endl;
        return 1;
    }

    string line;
    while (getline(inFile, line)) {    // reads one line at a time until EOF
        cout << line << endl;
    }

    inFile.close();
    return 0;
}

Reading Word by Word (using >>)

ifstream inFile("data.txt");
string word;
while (inFile >> word) {   // reads a single whitespace-delimited word at a time
    cout << word << " ";
}
inFile.close();

Reading Mixed Data (numbers and text)

// Assume file contains: "Vinit 22" (name and age, space-separated)
ifstream inFile("student.txt");
string name;
int age;
inFile >> name >> age;    // works exactly like cin >> for mixed types
cout << name << " is " << age << " years old" << endl;
inFile.close();

4. File Modes

File modes control exactly how a file is opened — whether to append, truncate, read in binary, etc. Passed as a second argument to the stream constructor (or .open()).

Mode flagMeaning
ios::inOpen for reading (default for ifstream)
ios::outOpen for writing (default for ofstream) — truncates by default
ios::appAppend — all writes go to the END of the file, existing content preserved
ios::ateOpen and immediately seek to the end (but writes can still happen anywhere, unlike app)
ios::truncTruncate — erase existing content on open (this is the default with ios::out)
ios::binaryOpen in binary mode (no text translation of newlines, etc.)
 
ofstream outFile("data.txt", ios::app);   // append mode — preserves existing content
outFile << "New line added at the end" << endl;
outFile.close();

// Combining multiple modes with the bitwise OR operator
fstream file("data.txt", ios::in | ios::out | ios::app);

5. Checking Stream State

ifstream inFile("data.txt");

if (!inFile) { /* ... */ }        // shorthand — true if the stream is in a FAILED state
if (inFile.fail()) { /* ... */ }    // explicit check for a failure state
if (inFile.eof()) { /* ... */ }       // true once end-of-file has been reached
if (inFile.is_open()) { /* ... */ }     // true if the file is currently open

Common gotcha — checking eof() BEFORE reading is a classic bug:

// WRONG pattern — often reads the last line TWICE (or produces one extra empty iteration)
while (!inFile.eof()) {
    getline(inFile, line);
    cout << line << endl;
}

// CORRECT pattern — let the read operation itself control the loop
while (getline(inFile, line)) {
    cout << line << endl;
}

The reason: eof() only becomes true after a read attempt has already failed to find more data — checking it beforehand is one iteration "too early," which is why the read-in-the-condition idiom (while (getline(...)) or while (cin >> x)) is always the correct pattern.

6. Working with an fstream for Both Reading and Writing

fstream file("data.txt", ios::in | ios::out);

string line;
while (getline(file, line)) {
    cout << line << endl;
}

file.clear();                    // must clear the eof/fail flags before further operations
file.seekp(0, ios::end);          // move the WRITE position to the end
file << "Appended via fstream" << endl;

file.close();

7. File Position Pointers — seekg / seekp

FunctionPurpose
seekg(pos)Moves the GET (read) position
seekp(pos)Moves the PUT (write) position
tellg()Returns the current GET position
tellp()Returns the current PUT position
 
ifstream inFile("data.txt");
inFile.seekg(0, ios::beg);  // move to the beginning
inFile.seekg(0, ios::end);    // move to the end
streampos size = inFile.tellg(); // get current position (useful to compute file size)
cout << "File size: " << size << " bytes";

8. Why Always Close (or Let RAII Close) Files

File stream objects (ifstream, ofstream) automatically close the file in their destructor when they go out of scope — so explicit .close() calls aren't strictly mandatory if the stream object's lifetime naturally ends soon after. However, calling .close() explicitly (and checking for errors) is good practice, especially before reusing the same stream object to open a different file. 

void writeData() {
    ofstream outFile("log.txt");
    outFile << "Some data";
    // even without explicit .close(), outFile's destructor closes the file here automatically
    // when writeData() returns — this is RAII in action (Module 2.2 / Module 5.3)
}
