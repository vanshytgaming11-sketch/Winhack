Module 3.1 — Templates

Templates let you write a single function or class that works with any data type, without duplicating code for each type. The compiler generates a specific version of the function/class for each type actually used, at compile time — this is called generic programming, and it's the foundation the entire STL (Module 4) is built on.

1. Function Templates

Without templates, you'd need to overload the same logic manually for every type:

int maxInt(int a, int b) { return (a > b) ? a : b; }
double maxDouble(double a, double b) { return (a > b) ? a : b; }
// Repetitive — same logic, different types

A function template eliminates this duplication:

template <typename T>
T maxVal(T a, T b) {
    return (a > b) ? a : b;
}

int main() {
    cout << maxVal(3, 7) << endl;         // T deduced as int → 7
    cout << maxVal(3.5, 2.1) << endl;       // T deduced as double → 3.5
    cout << maxVal('a', 'z') << endl;         // T deduced as char → z
    cout << maxVal<double>(3, 7) << endl;       // explicit instantiation — forces T = double
    return 0;
}

typename and class are interchangeable in this context — both just mean "T is a placeholder for some type":

template <class T>   // equivalent to `template <typename T>`
T maxVal(T a, T b) { return (a > b) ? a : b; }

How Compilation Works — Template Instantiation

Templates aren't compiled into a single generic function. Instead, the compiler generates a completely separate, concrete version of the function for each distinct type it's called with — this process is called instantiation. Calling maxVal(3, 7) and maxVal(3.5, 2.1) effectively produces two separate compiled functions, maxVal<int> and maxVal<double>, even though you wrote the logic only once.

Multiple Template Parameters

template <typename T1, typename T2>
void printPair(T1 a, T2 b) {
    cout << a << " " << b << endl;
}

int main() {
    printPair(1, "hello");    // T1 = int, T2 = const char*
    printPair(3.14, 'x');       // T1 = double, T2 = char
    return 0;
}

2. Class Templates

The same idea applies to entire classes — a template class can hold or operate on data of any type.

template <typename T>
class Box {
    private:
        T value;
    public:
        Box(T v) : value(v) {}

        T getValue() {
            return value;
        }

        void setValue(T v) {
            value = v;
        }
};

int main() {
    Box<int> intBox(42);           // T = int
    Box<string> strBox("Hello");     // T = string

    cout << intBox.getValue() << endl;    // 42
    cout << strBox.getValue() << endl;      // Hello
    return 0;
}

Note: unlike function templates, class templates require explicit type specification at instantiation (Box<int>) — the compiler cannot deduce T from constructor arguments alone in all C++ standards (C++17's Class Template Argument Deduction, or CTAD, relaxes this in specific cases, covered briefly in Module 5).

A More Complete Example — Generic Stack

template <typename T>
class Stack {
    private:
        vector<T> data;
    public:
        void push(T val) {
            data.push_back(val);
        }

        void pop() {
            if (!data.empty()) data.pop_back();
        }

        T top() {
            return data.back();
        }

        bool isEmpty() {
            return data.empty();
        }
};

int main() {
    Stack<int> s;
    s.push(10);
    s.push(20);
    cout << s.top(); // 20
    s.pop();
    cout << s.top();  // 10
    return 0;
}

3. Template Parameters — Type vs Non-Type

Templates can also accept non-type parameters — constant values known at compile time, not just types:

template <typename T, int SIZE>    // SIZE is a NON-TYPE template parameter
class FixedArray {
    private:
        T data[SIZE];
    public:
        int length() { return SIZE; }

        T& operator[](int index) {
            return data[index];
        }
};

int main() {
    FixedArray<int, 5> arr;    // creates a fixed array of 5 ints, SIZE baked in at compile time
    arr[0] = 10;
    cout << arr.length();       // 5
    return 0;
}

4. Default Template Arguments

template <typename T = int>
class Container {
    T value;
    public:
        Container(T v) : value(v) {}
        T get() { return value; }
};

int main() {
    Container<> c1(10);        // uses default T = int
    Container<double> c2(3.14); // explicit T = double
    return 0;
}

5. Template Specialization (brief introduction)

Sometimes the generic template logic doesn't make sense (or needs special handling) for one specific type — template specialization lets you provide a custom implementation for that particular type. 

template <typename T>
class Printer {
    public:
        void print(T val) {
            cout << val << endl;
        }
};

// Full specialization for bool — prints "true"/"false" instead of 1/0
template <>
class Printer<bool> {
    public:
        void print(bool val) {
            cout << (val ? "true" : "false") << endl;
        }
};

int main() {
    Printer<int> p1;
    p1.print(42);          // 42

    Printer<bool> p2;
    p2.print(true);          // true (not 1) — uses the specialized version
    return 0;
}

6. Why Templates Matter for the STL

Every STL container you'll use in Module 4 — vector<T>, map<K,V>, stack<T> — is itself a class template. Understanding templates here is what makes the STL's syntax and behavior make sense rather than feeling like memorized magic. 

vector<int> v;       // vector is a class template; int is the template argument
map<string, int> m;   // map takes TWO template parameters — key type and value type

  2. What is the difference between a type template parameter and a non-type template parameter? Give an example of each.
  3. Why must class templates usually specify their type explicitly (Box<int>) while function templates can often deduce it automatically from arguments?
  4. What is template specialization, and when would you need it?
